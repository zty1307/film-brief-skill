# 影视简报清洗执行流程

## 统一执行入口

生产运行只使用 `scripts/film_workflow.py` 建立独立工作区和推进流程。执行者不自行判断下一条底层命令；每次读取 `<独立工作区>/workflow_status.json`，只按其中唯一的 `stage`、`required_file` 和当前 `input_file` 完成当前语义任务，再运行 `advance`。来源复核和最终摘录复核按每批最多60条推进，控制器每轮只暴露下一片未完成内容，并把小份提交自动合并到脚本账本；不要复制历史答案或提前读取其他分片，`full_input_file` 仅供核对完整性。初次观点发现需要全局归纳，是唯一应依次读取全部 `input_files` 的阶段。模板中的 `_workflow` 绑定块必须原样保留。

先通过 Codex 的 workspace dependencies 取得捆绑 Python 路径，避免调用 Windows Store 的同名占位程序。实战前用同一组路径运行 `doctor`；只有全部检查为 `PASS` 才执行 `init`。

已有期次配置时，`doctor` 和 `init` 都传入同一份配置：

```powershell
<python> scripts/film_workflow.py doctor --source <原始数据目录> --period-config <period_config.json> --workspace <独立工作区> --output <单期工作台.html>
<python> scripts/film_workflow.py init --source <原始数据目录> --period-config <period_config.json> --workspace <独立工作区> --output <单期工作台.html>
```

尚无期次配置时，两个命令都不传 `--period-config`；`init` 会生成模板并停在 `period_config` 审核阶段：

```powershell
<python> scripts/film_workflow.py doctor --source <原始数据目录> --workspace <独立工作区> --output <单期工作台.html>
<python> scripts/film_workflow.py init --source <原始数据目录> --workspace <独立工作区> --output <单期工作台.html>
```

初始化后只重复以下命令；需要查看状态时使用 `status`：

```powershell
<python> scripts/film_workflow.py advance --workspace <独立工作区>
<python> scripts/film_workflow.py status --workspace <独立工作区>
```

`advance` 会连续执行可以确定完成的脚本步骤，遇到需要 AI 判断的关口正常停止。只有 `COMPLETE` 表示机器验收通过；`REVIEW_REQUIRED` 表示必须补齐语义评审；`BLOCKED` 或 `BROKEN` 必须修复，不能通过直接调用底层脚本绕过。同一工作区禁止两个执行者同时运行 `init`、`status` 或 `advance`。控制器会在 `workflow.lock` 上申请操作系统文件锁，进程退出或崩溃后由操作系统自动释放；磁盘上保留的 `workflow.lock` 只是锁载体，不是陈旧 PID 文件，不要人工删除或改写。

## 1. 数据盘点与标准化

原始目录以“一个子文件夹对应一个剧集期次”为默认结构。只读取当前期的渠道数据文件；同目录中的历史报送 Word 仅登记文件存在，不解析正文，也不进入清洗。

脚本读取 Excel、核对表头、记录文件哈希、原始文件名、工作表和行号，并生成稳定来源 ID。AI只在表头含义发生变化时判断字段映射，随后把映射固化到配置，不逐行手工搬运。

## 2. 字段隔离与初筛

正式记录只保留批次、渠道、帖子类型、时间、标题、正文、ASR、必要的父帖上下文、作者、链接和原始定位。任何历史命中、质量分、卡片、旧簇、旧摘录、旧去留或人工分层字段都必须剥离。

目标词必须分层配置：作品全名、完整节目名、官方专属话题和从当期标题或话题标签确认的唯一简称写入 `strong_terms`；可能泛指题材或其他内容的简称写入 `weak_terms`；演员、嘉宾、主创和角色名写入 `auxiliary_terms`；同期对比作品写入 `comparison_terms`。辅助人物词不能单独确认作品，弱目标词不能直接自动准入。配置前先抽取当期高频标题和话题标签，确认“脱友3”这类真实唯一简称，不能只凭经验列别名。

脚本先处理明确情况：目标无关、同名误召回、只有排播片单、只有剧情复述且不存在评价句、演员私生活、空泛短评、纯宣发导流、饭圈物料、无 ASR 短视频。正文自身出现“本文由AI生成”、面向模型的改写要求、只给正文等输出指令，或模型对写稿任务的元话语时，整条来源直接排除，不再截取其中局部段落；节目或行业内容正常讨论AI技术不触发该规则。自动准入还要求强目标词与评价判断、分析维度或具体细节出现在同一局部窗口；作品全名明确写在单一作品标题时，可由标题确认对象，再在正文寻找评价依据。只在全文远处偶然出现作品名、只命中弱简称、只命中演员或角色名、同一评价窗口混入对比作品时，均不得直接自动保留。文章含有排播、剧情或跨剧内容时，仍要搜索其中是否存在可独立成立的评价片段，不能按文章类型整篇删除。内容分只用于排序与发现边界样本；已经具备“目标对象 + 评价判断 + 支撑依据”的低分来源进入 `retain_consensus`，不能被分数阈值直接删除。

账号媒体属性采用“精简核心库 + 已核验补充库”。核心库只预置中央重点媒体、广电及影视文化专业媒体和少量高频地方主流媒体；其余媒体在真实数据中出现后再核验补充。主体记录母机构、媒体等级、库内分组、已核验账号别名、账号类型和必要的第一方官网域名。脚本依次检查账号全名、已核验第一方官网域名和认证主体：账号名称必须精确命中；官网仅用于媒体自有域名；认证信息仅在“认证类型”为媒体、认证主体唯一包含库内母机构或长度不少于4字的已核验别名时生效。单独出现“媒体”认证、个人“媒体人”认证、节目官号或播出平台认证均不能提升为主流媒体。聚合站、转载站、社交平台和分发平台域名不得作为媒体归属依据。经确认的评论、文艺等官方垂直账号继承母机构等级，同时保留垂类类型。不得因为昵称包含“新闻、日报、传媒、电视台、网”等字样自动提升。新账号或域名由AI或人工核验认证主体、所属机构或第一方主页后，再作为 `media_subject_extensions` 增量加入；无需为每个平台重复建主体。播出平台、节目官号和参与者账号另作一手信息源理解，不自动算主流新闻媒体。

为找回“正文省略节目名、只写当期热搜事件”的短评，脚本从已经明确命中强目标的当期来源中统计反复共现的话题标签和事件名：至少与强目标共同出现2次，或在当期独立出现3次，才写入 `derived_context_terms.json`。这些当期词只负责把边界短评送入AI全文复核，不能自动保留；演员姓名和嘉宾姓名仍只属于辅助词。这样既能找回具体事件评论，也不会把人物参加的其他剧综一并吸入。

## 3. 当前期全文语义复核

`prepare` 输出精简语义复核队列，并为每条边界来源给出最多三个逐字候选窗口及其 `candidate_index/start/end`。规范化全文完全相同的同稿只保留一个代表项；AI审核一次，`select` 将决定传播到同稿组。当前分片不重复整篇正文、全文回查说明、脚本命中词和质量中间量；候选不足时才按状态文件给出的统一路径和 `source_id` 回查全文。AI判断是否存在“明确评价对象 + 明确判断 + 可复核依据”，优先填写 `evidence_candidate_index`；控制器自动还原逐字原文与字符位置，并在链接检查前一次列出格式错误。

明显规则项可以由脚本直接决定。来源级 AI 队列主要收纳“脚本准备排除、但全文仍可能夹有有效观点”的边界项，例如多剧混写、资料或剧情复述中夹带评价、长文宣发和以演员信息开篇但后文评价作品的内容。另有两类安全信号会强制送审，即目标作品只出现一两次、正文却集中出现多名未配置角色的疑似跨剧错置，以及包含人身攻击或仇恨措辞但仍可能夹有有效舆情判断的内容；这两类只送AI判断，不由词表自动删除。

电视剧按连续剧情和日更窗口处理。周更综艺先由AI完成期次归属：最新一期是主分析池；前一期只有在当前监测周新出现明显传播、跨来源讨论、权威媒体跟进或实质风险时才可作为 `previous_episode_prominent` 纳入，并逐条记录期次证据与突出依据；日常余波和更早期次排除。无法明确期次的来源不得直接进入工作台。脚本负责日期窗口和字段校验，AI结合本期嘉宾、选手、环节与话题判断实际归属。

`episode_scope` 是来源级审计结果，归簇和生成页面时不得按簇标签回写或覆盖。普通综艺簇中每条成员保存的期次范围必须与簇范围一致；不一致时移动样本或拆簇。只有标题明确说明跨期、且集合审查记录合并理由时，才允许 `mixed_scope_explicit`。

## 4. 同稿与洗稿去重

来源复核通过后，控制器先生成 `source_link_candidates.jsonl`，只包含此时仍可能保留的来源，再交给 `check_links.py`。脚本不访问已经因内容被排除的链接，并对目标和每次重定向先做禁用域名检查；仅当两次GET都返回404或410时写为 `confirmed_dead` 并在来源层排除。401、403、429、登录墙、反爬、5xx、DNS错误和超时写为 `indeterminate`，继续保留。

`select` 在同一批次内计算规范化三字切分的 Jaccard 相似度和包含率。达到任一阈值时进入重复候选：`J≥0.84`、`C≥0.94`、或 `J≥0.28 且 C≥0.58`。组内先比较已经核验的主流媒体身份，再比较渠道优先级、正文完整度和内容质量。同一主流媒体把同一稿件分发到多个平台时仍按同稿去重，优先保留正文完整、链接可用的版本。

完全相同和高置信同稿由脚本合并。处在相似阈值附近的来源在生产流程中默认视为独立表达并保留，避免把“观点相似”误判成“同稿”。`dedup_audit.json` 仍记录这些候选供离线抽查，但不再形成必须逐对填写的AI关口。

## 5. 当期观点簇发现与归类

AI依次通读控制器列出的 `cluster_discovery_chunks/chunk-*.jsonl`，从当期反复出现的真实表达中归纳簇。脚本按立场和渠道从全量保留池分层抽取每批最多180条发现样本；这一步只降低初次阅读量，全量来源随后仍会归簇并检查遗漏方面。每条保留一个逐字观点候选、来源ID和必要元数据；片段语义不清、疑似跨作品或需确认范围时，再按ID回查 `retained_sources.jsonl` 中对应全文。簇名使用可直接理解的报告体观点句。每个非背景簇还须给出1—4个方面词或短语；作品名、演员名、角色名和“剧情、热度、好看”等通用词不能单独承担归簇。先按样本形成观点，再标记正面、客观或负面；不沿用上一期角色词，不把正式报告结构当答案，也不设置兜底簇。

聚类单位是共同的评价机制或可直接写入简报的命题。人物、角色、嘉宾、单个段子、名场面和热梗通常作为论据或细分主题；只有它本身形成独立传播、风险或制作价值时，才可成为一级观点。不同作者表达相近意思时全部保留，用于提供人工选样空间。只有一两条来源的语义独立观点也可保留，不能按数量删除或强并。

脚本先寻找包含目标作品的局部窗口，再计算观点证据和立场。作品名不参与观点得分，演员或角色名只给极低辅助权重，方面词和局部立场承担主要得分，避免一个高频主演吞并音乐、制作、剧情等观点。两个相近观点都可承接时采用得分更高者，不要求逐条裁决。当大量来源出现 `passage_aspect_mismatch` 时，控制器先返回 `cluster_definition_repair`，并提供最多40条缺口样本；执行者应补充遗漏观点或同义方面词，不能为几十上百条来源逐条写覆盖项。少量目标不明、立场冲突、跨作品或缺少主题证据的残余按每批最多60条进入 `cluster_overrides.json` 提交。若一个完整观点分布在两个不相邻位置，AI可填写一至两段逐字 `passage_fragments`；控制器核对位置、顺序和不重叠关系。最终摘录复核负责每条展示文字的完整语义判断。

执行者每轮只填写控制器当前模板中的残差ID。控制器把上轮已经通过的记录保存在与当前输入指纹绑定的 ledger 中，当前同一来源ID的修改覆盖旧值，其余旧记录自动保留；执行模型无需读取、复制或维护历史覆盖项，也不会因小文件提交导致上一轮结果失效。

多剧对比文章必须在段落级识别评价对象。片段只谈另一部作品时直接排除；同段同时出现多部作品时，必须由AI记录目标作品的原文锚点和判断归属，脚本不得仅凭文章标题或全文出现过剧名自动放行。

## 6. 观点簇集合与整期数量审查

首次运行 `cluster` 后，脚本根据簇标题、立场和实际成员生成 `cluster_set_review_input.json`，并计算包含标题、立场和全部成员来源ID的指纹。为控制输入体积，每簇只展示最多8条按工作台优先级排序的代表样本。AI拆解标题中的每个主张，并为每项列出至少一个实际支持来源；同时检查全簇共享的评价关系、立场纯度、时间或期次范围、来源角色和颗粒度。标题各分句分别有来源支持仍不足以通过集合审查，不能用宽泛结果连接互不推出的判断。逐样本的对象、方面、立场、作品一致性和自足性统一在最终摘录复核中完成一次。

每簇标记为 `report_point`、`subtopic`、`data_note` 或 `rare_signal`。工作台最终只展示这一层观点簇，不再额外生成“大观点—细分主题”结构。正面、客观、负面分别聚类，背景数据只能进入客观簇。普通单期以9—16个最终观点簇作为人工阅读负荷的审阅区间。该区间不参与来源准入，也不允许按数量删样：超过16个时，AI复查是否因人物、单个段子、相近措辞或同一评价机制而过度切碎；少于9个时，AI复查是否存在标题罗列多个方面、成员由不同机制支撑的“大口袋簇”。只有当调整后簇内所有成员仍能共同支持一个准确的报告体命题时，才允许重新归并或拆分。若继续调整会损害语义质量，可以越界，但必须填写逐期例外原因。脚本只负责计算簇数、核对9—16区间、绑定当前簇名与成员指纹和拦截未审结果，不根据数量自动合并、拆分或删除。

第一次运行 `cluster` 时，脚本同时生成逐簇的 `cluster_set_review_input.json` 和逐期的 `cluster_count_review_input.json`。每簇最多展示8条代表样本，完整成员ID仍进入指纹。脚本预填指纹并计算实际簇数和范围；AI只返回结论、问题列表、总理由、观点标题证据以及必要的报告角色和范围类型，不重复抄写数量或填写多组同义确认项。通过时 `issues` 保持空数组。若修改簇定义或成员归属，指纹自动失效并按最终簇重新审查。

归簇残差在 `cluster_assignment_review` 中修复；最终展示文字的逐条语义问题在 `final_excerpt_review` 中修复。同一成员不再因相同问题填写两套复核文件。

## 7. 阅读顺序与页面折叠

对象、方面、立场和逐字证据均通过的独立来源全部保留在工作台数据中。脚本只负责排序：同簇内先放已核验的主流媒体账号，账号身份跨越境内新闻、公众号、今日头条、微博和小红书生效；再覆盖不同渠道和表达方向，并兼顾来源质量和文字可读性。媒体身份只改变阅读顺序，不能绕过观点质量门槛，也不删除独立网民或自媒体表达。页面默认显示每簇前若干条，其余内容通过“展开更多”查看。相似观点不会直接删除独立来源；只有同稿、转载和明确改写稿才去重。方法中不设置按期或按簇的阅读数量公式，也不允许在已经合格的展示数据上再次截断。

正面、客观、负面分别计算和展示。立场以最终展示片段为单位：正面簇只选局部结论明确肯定的片段，负面簇只选局部结论明确批评的片段，客观簇用于播出背景、市场数据或明确描述正负分布的中性概况。全文存在反转或混合态度时，AI可以截取其中自足且不重叠的正面、负面片段分别归类；当前期没有可靠负面样本时不强行生成负面簇。

## 8. 原文摘录

脚本按句子边界生成候选并记录字符位置；无规范标点的长文继续按换行、项目符号、话题标签、逗号、转折词和最大字符窗口分层切分。AI优先选择“完整判断 + 同主题支撑”的一至两句，清洁后的展示文字以70—150字为优先区间。短于70字时回到全文补充同观点、同立场的具体依据；全文确实无内容可补时，只有当前短评仍包含具体台词、动作、情节、表演处理、争议事实或分析依据才可保留，并记录逐条例外理由及逐字具体依据。仅有作品标签、人物名和“好看、封神、绝了、笑点拉满、期待”等泛泛态度时排除展示。不得拼接无关背景凑字。超过150字必须压缩为完整原文句段，不能在句中硬截。遇到先扬后抑、先抑后扬、跨作品比较或正负清单，先回到同一来源全文寻找能独立成立的局部判断，找不到后才排除展示。默认连续；若非连续片段能自然连接、明确指向同一簇且顺序不变，可选两段。展示端可以不加省略号，后台必须保存每段原文及起止位置。片段不得以截断符开头或结尾。

进入语义终审前，脚本只对展示层做可复算的删除式清洁：同时兼容成对话题与只有前导井号的连续标签；在末尾连续标签串 `#节目#嘉宾` 中，第二个 `#` 是第二个标签的起点，两个标签均删除。脚本还会去掉账号标记、平台表情和方括号表情、Markdown或裸链接、共创视频等分享尾巴及不可见控制符。正文和后台原文片段不改，字符位置继续指向原始来源；页面展示清洁后的评价句。不得从话题标签内部单独摘出剧名、节目名或事件词回填展示摘录。来源级对象与期次审核可以使用原始标签作为上下文，工作台的批次、观点簇和来源卡片负责向读者交代所属作品与期次，因此一条意思完整的短评无需在摘录中重复这些元数据。清洁后为空、仅剩标签/账号/链接，或只剩无法表达观点的口号时回看全文重截；仍无独立正文才排除。脚本同时标记抽奖、购票、报名、二维码、礼包和活动规则等促销操作词；它们只触发AI核验。AI必须从最终摘录中指出独立观点原文才可保留，纯操作说明或演员履历排除；正文另有有效评价时重截评价，不按来源类型整篇删除。

`render` 首次运行会生成最终摘录语义复核输入。脚本先核对作品锚点、对比作品词、长度、社交标记清洁和逐字位置，再把清洁摘录无损切成按顺序编号的 `excerpt_segments`。AI读完这些片段，只选择方面证据和立场证据编号，并判断立场与自足性；普通 `keep` 不写理由、不复制原文，脚本负责回填逐字证据。候选均不适用时才填写原文兜底。仅在明确标记对象、跨作品、短摘录或促销风险时增加对应条件项。能够重新截出合格原文时先改摘录；片段只是方面或立场错配时先尝试转簇。全文确实没有合格展示段时，`drop` 才填写具体理由、失败项和重截或转簇记录。终审逐条判断，不设样本数量或阅读预算；所有合格独立表达均保留。

## 9. 工作台生成与验收

工作台只展示通过四项校验的样本。左侧按单期列出批次；批次超过视窗高度时列表独立滚动，最后一项必须能够完整显示和点击。正文顶部用“正面、客观、负面”切换组件选择立场，每个切换项同时显示该立场的样本数和观点簇数；正文直接展示一级观点簇，不再设置父子层级。页面同时报告样本数和观点簇数，没有样本的立场不显示切换项。页面可搜索当前立场、展开原文和主动打开来源，样式与数据全部内嵌，离线可用。

发布前必须验证：最近一次 `render` 成功且失败项为空、HTML内嵌数据与 `workbench_dataset.json` 完全一致、所有复核队列清零、对象与方面与立场及作品内部信息一致、原文位置与展示清洁可复算、无空簇和兜底簇、无远程资源及禁用链接。`render` 只能写工作区内的 `workbench.verified-candidate.html`；`verify` 通过后控制器才把该文件原子发布到正式输出路径。执行者不得自行创建、复制或替换正式HTML。

## 10. 累计工作台合并

每个新增或重跑批次先独立完成 `render` 和 `verify`，通过后再并入累计工作台。合并时把现有累计工作台放在输入列表第一位，后面按需要放一个或多个已验收的单期工作台。脚本以批次名称为键：同名批次在原位置整体替换，新批次追加到左侧期次列表末尾，未涉及批次的数据对象不变；页面的 HTML、CSS 和交互脚本沿用第一个输入，只更新内嵌 `DATA`，因此不会因单期脚本升级而改变总工作台样式。

```powershell
<python> scripts/film_workflow.py merge --inputs <现有累计工作台.html> <已验收单期工作台.html> --output <累计工作台.html> --backup-dir <备份目录> --report <合并校验报告.json>
```

合并前，脚本核对每个输入的批次名、簇数、样本数、立场、逐字原文位置、语义复核状态、重复 ID、远程资源和禁用链接。历史累计工作台只允许作为第一个输入，并按其原有审核字段做兼容校验；后续新增或替换批次必须使用当前完整审核格式。目标文件已存在时先生成时间戳备份，再写临时文件、重新解析并校验，全部通过后才原子替换正式文件。任一输入失败时只写失败报告，正式工作台保持原样。

## 故障定位边界

生产执行者只运行控制器给出的 `advance`，不得根据本页手工拼接底层 `prepare`、`select`、`cluster`、`render` 或 `verify` 命令。底层命令只在控制器返回 `BROKEN` 后用于定位问题；修复完成后仍回到 `status/advance`。`source_review_queue.unresolved.jsonl`、`cluster_review_queue.jsonl`、`cluster_set_review_queue.unresolved.jsonl`、`cluster_count_review_queue.unresolved.jsonl` 或 `excerpt_semantic_review_queue.unresolved.jsonl` 任一非空时，均不得发布。正式输出路径存在但没有本轮 verify 记录的匹配哈希时，控制器返回 `BLOCKED / unverified_output`。

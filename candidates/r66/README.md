# r66：影视剧单窗口30分钟候选版

这是用于人工撰写简报的证据工作台 Skill，不是无需人工检查的正式报告生成器。默认面向影视剧，不声称本次完成综艺验证。

## 下载与使用

下载 [`film-brief-cleaning-r66.zip`](../../dist/film-brief-cleaning-r66.zip)，解压后使用其中的 `film-brief-cleaning` 文件夹。也可直接取本目录下的同名源码文件夹；它包含本轮实际测试过的21个生产文件。不要把仓库根目录的旧版文件混入新版。

使用 Python 3.10+，先在该文件夹下安装 `requirements.txt`。在一个 WorkBuddy 主窗口提供本期原始 Excel 目录、本期剧名和一个新的输出工作区，并让模型完整读取该文件夹的 `SKILL.md`。有原生 Agent 工具时由主窗口按 Skill 派发内部任务，不另外启动外部模型/CLI 窗口。

可用任务描述：

> 请读取并按此处 film-brief-cleaning/SKILL.md 的默认流程处理本期原始 Excel。剧名、原始目录和新工作区以我提供的信息为准。形成9—16个本期观点簇，每组最多10条不同来源的代表摘录，满10停止；不要全量来源复核或反复改簇。用原模板输出 workbench.html。从任务开始计时，总墙钟上限30分钟，包含原生任务关闭和主窗口退出；未满组、未交卷或有限编辑未完成必须如实说明，不把未审样本展示出来。

## 主要变化

- 标题恢复为完整报告式观点句，通常24—36字，保持一个核心主张；原HTML布局、交互不改。
- 脚本处理全量原表、去重、粗分与排序，保留长段落后部候选，识别局部否定；AI只读限量代表包做一次观点发现。
- 正负观点采用一致的层级与颗粒度，补充独立正面机制的发现机会，不设正面多数配额。
- 完整标题与短检索词分开，避免用长句检索造成候选漏召回。
- AI审核实际展示候选：不合适才补下一条，满10停止，不重审已通过条目。
- 预算有余时主窗口做一次最多240秒的有限编辑，每组最多3条、总计最多48条；已固定标题的证据编号由脚本绑定实际保留结果，不把编号整理当语义审批。

上述是四次观测，不是稳定成功率或任意数据30分钟保证。额外硬截止由本次测试外层监控执行；Skill内部按预算收尾，在其他宿主中仍需可靠的时间/取消机制，不能把提示词等同于进程级强制截止。

## 必须保留的限制

- A有5条补样未交卷，连续300秒无新增判定后停止补样；5条不展示，不可说全部候选已审完。
- B额外编辑触及240秒上限，保留已通过初审的结果；不能说额外质量检查成功。
- B/C因下一轮预算不足停止补样，未满10不等于候选耗尽；D为满额或候选耗尽。
- 部分分组仍有交叉，部分标题包含两层主张而单条摘录只支持一层；少量宣传表达或其他作品履历仍可能残留。
- “网传/暂定”等来源说法不能在正式报告中升级为已核实事实。没有联网验证文章真实性、热度指标口径或人物争议。
- 仅展示句经过初审；有限编辑只抽查包内条目，不是全部展示句二审，更不是后台全量来源核实。

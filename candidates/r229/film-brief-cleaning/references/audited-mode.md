# Film Brief Cleaning

Generate an information workbench for human report writing. Preserve the complete backend evidence pool and script grouping. For each data-derived one-level viewpoint cluster select at most 10 different independent sources that definitely support it; stop that cluster after 10 confirmed samples. Do not draft the final report.

## Generalization boundary

This is a reusable Skill across works and periods, not a solution keyed to one benchmark. Work names, dates, people, episode scope and derived topics belong only in current workspace configuration/data. Never embed benchmark IDs, expected decisions or cluster names in production rules. The 10-sample ceiling is a general report-selection rule, not a desired cleaning count. Never delete unused qualified backend sources or call them invalid. Admission/exclusion changes still require real cross-period checks. Prior model reviews are diagnostic evidence, not human gold labels or answers to inject into a fresh run.

## Representative selection rule

New workspaces use `representative_sample_limit: 10`. Keep it when filling period configuration. This overrides older full-display instructions: select and review only enough candidate sources to obtain at most 10 confirmed supports per group, not every member followed by truncation. Pending candidates reserve remaining slots but do not count as confirmed. Replace a rejected or explicitly unselected candidate with the next different source. Fewer than 10 is valid; do not fabricate, pad, drop rare viewpoints or enforce a minimum. The same reviewed media parent or known author counts once in one group. Background script groups and unselected evidence remain available for human audit.

Scripts preserve full provisional grouping and coverage doubts, defer unused individual route issues, and send an ordinary route candidate when a group otherwise has no eligible evidence. Major coverage gaps still require a bounded definition check; cluster-set review still checks titles and representative evidence. Final selected keeps must pass all existing target/aspect/stance/excerpt gates. In final inputs explicitly marked `representative_selection: true`, `decision: not_selected` with a current excerpt evidence index and concrete reason means only “not this group's representative”; it is not a drop, applied reassignment or invalid source. Do not exhaustively re-excerpt/reassign unused candidates. Ordinary semantic drops and explicit reassignment requests retain their original stricter contracts. Completed groups receive no further candidate review. Legacy workspaces without this configuration key retain their old full-display behavior; do not use them as new-rule benchmarks.

## Execution priority

Target a complete run within 30 minutes on an ordinary model. Preserve usable evidence and basic work/stance correctness; do not pursue perfect wording or one-to-one agreement with a finished report. Read only each current packet, submit once, and repair only reported errors. Do not generate stage essays or extra audit narratives. This is a runtime target to measure, not a claim that every model or dataset will meet it.

The user starts one host conversation with this Skill and raw data. The entire run must finish inside that conversation without another operator launching models or supplying review answers. Use the host's bundled Python from its environment instructions. Start timing with the user's request, including model reading, tools, retries, and final verification; interrupted checkpoint runs do not establish a continuous 30-minute result.

## Native review inside one conversation

When the host exposes a native `Agent` tool that inherits the main model, use it for `source_review`, `cluster_assignment_review` residual packets, and `final_excerpt_review`. Read [native-review.md](native-review.md) at the first such stage. The controller prepares bounded, disjoint packets and collects files; it never launches a CLI or calls a model. The main conversation invokes the native agents, all using the same model as the main conversation. On WorkBuddy use `subagent_type="general-purpose"`, `model="default"` (inherit parent); do not substitute a stronger model. If no inheriting native tool is available, keep processing serially through the ordinary controller and report that mode.

WorkBuddy calls must also include `run_in_background=true`, exactly as returned in each `workbuddy_agent_input`. Omitting it makes the call synchronous. Start all jobs before waiting, including after context compression or resume; do not reconstruct the argument object while dropping this field.

When assignment definitions change, the controller may offer guarded prior proposals with complete definition deltas. Read current evidence and explicitly confirm each still-valid proposal, or submit a full new judgment; do not rewrite unchanged evidence fields unnecessarily. An old judgment is never automatic approval. Changed selected definitions, source/config/rule drift and other workflows require ordinary new judgments. See the exact confirmation contract in [native-review.md](native-review.md); final excerpt and machine/visual gates remain unchanged.

Other stages remain with the main conversation. Native review is the only exception to the single-current-packet/write-only rule below: children read and write only their assigned files, while the parent alone invokes controller mutations. Never launch extra CLI sessions or use external model orchestration.

## Hard execution gate

- Production runs use only `scripts/film_workflow.py`. Call `film_pipeline.py` directly only to diagnose a controller failure.
- During normal `READY_TO_ADVANCE` or `REVIEW_REQUIRED` states, read only the current input, template, and referenced contract. Do not inspect script source, scan every run artifact, or create helper programs; those actions are reserved for a real `BROKEN` diagnosis.
- Never create, edit, copy, or rename an HTML file into the requested output path. The controller writes a staged candidate, verifies it, and publishes the official HTML only after `verification.json` is `PASS`.
- Deliver only when `workflow_status.json` says `COMPLETE`. An existing HTML, `REVIEW_REQUIRED`, `BLOCKED`, or `BROKEN` is not a result.
- Do not replace failed semantic reviews with exclusions merely to finish. Correct the evidence, assignment, cluster definition, or excerpt indicated by the status file.
- A controller submission has one writer. Never issue parallel `Edit`/`Write` calls against the same file: compose all changes into one write, or edit sequentially and reread the saved file before `advance`. Parallel reads of different files are fine; same-file writes can silently overwrite one another.
- At a title-only `cluster_definition_repair` with `title_format_repair`, read the returned small inputs and fill each definition's separate `write_only_files` answer with `title` and a current reason. Never edit `protected_parent_file`. Different definition files may be handled independently; each file still has one writer. Run the returned `next_command` to validate and merge all patches once under the workflow lock, then advance normally. Blank, partial, stale or invalid patches do not modify definitions; this merge does not approve semantic quality.
- `workflow.lock` normally remains on disk; ownership is an operating-system lock, released when its process exits. File existence alone does not mean a stuck task. On `WorkflowBusy`, wait for the active controller operation and retry; do not delete lock files, kill processes, or scan unrelated projects as a shortcut. Persistent busy errors require a bounded diagnosis, not forced concurrent advancement.

## Run the controller

Use Python 3.10+ and install `requirements.txt`. On Windows, use a real Python interpreter rather than the Microsoft Store placeholder.

```powershell
<python> scripts/film_workflow.py doctor --source <原始数据目录> --period-config <period_config.json> --workspace <空工作区> --output <单期工作台.html>
<python> scripts/film_workflow.py init --source <原始数据目录> --period-config <period_config.json> --workspace <空工作区> --output <单期工作台.html>
```

If no period config exists, omit `--period-config` from both commands and fill the generated template. After initialization, repeat only:

```powershell
<python> scripts/film_workflow.py advance --workspace <工作区>
```

Follow `workflow_status.json` literally:

- `READY_TO_ADVANCE`: run `advance` again.
- `REVIEW_REQUIRED`: the controller has already created the current editable submission at `required_file`. Read the current `input_file`, edit only the prefilled fields in `required_file`, save it, and run the exact `next_command`. Do not copy templates, inspect controller or pipeline source, create helper programs, or scan the run directory. The controller merges chunk submissions into its ledger. Never read all chunks up front. `cluster_discovery` is the sole exception: read every `readable_input_files` entry with the host file reader before defining clusters (legacy `input_files` only when reading views are absent). Use `full_input_file` only for auditing. When one item needs more context, run `operator_contract.source_lookup_command` with its ID (multiple IDs are supported); the returned `source_text` is the complete canonical text and position basis. Do not guess export field names or reconstruct title/body yourself.
- `BLOCKED` or `BROKEN`: fix the reported cause. Do not bypass the controller or invent another output.
- `COMPLETE`: open the published HTML, visually inspect the period tabs, stance tabs, cluster titles, excerpts, links, scrolling, spacing, and counts, then deliver it.

Failed final submissions carry field-level submission_errors directly in the current input_file. Correct those fields; do not reverse-engineer validators. Lexical hints can be corrected through an explicit semantic reason and never require deleting an otherwise usable source.

For native `review-dispatch`, use the returned `--as-file` command and read the complete `handoff_file` with the host file reader. Its UTF-8 content retains every job's exact inheriting/background arguments and collect/wait commands. The terminal returns only an ASCII JSON locator; do not redirect the handoff through PowerShell, parse/reprint it, or create a conversion helper. Legacy direct-output callers remain supported. Worker task files normally bundle all rules, assigned materials and the initial semantic template for one complete Read; when `reading_bundle_file` is present, do not reopen the separate input/initial template just to fetch the same data. Oversized bundles use the original lossless multi-file path. Repair workers must read their current answer file and preserve other completed entries; an embedded initial template is not a current answer or approval.

At `final_assignment_repair`, first check `operator_contract.scoped_patch`. For primary-only moves, run its `prepare_command` before reopening the entire assignment table. Read every returned `read_now` file and current definitions, fill only its semantic `write_only` patch with explicit cluster, local stance, reason and source-specific evidence indexes, then run its `apply_command` and `next_command`. The script verifies and merges once under the workflow lock; index selection restores literal text, never supplies a judgment. Ordinary window evidence gates also run before commit: repair returned source-specific errors only in the owned patch and reapply, not the global table. If the span genuinely expresses the aspect in words missing from the routing vocabulary, the model may supply meaningful verbatim `anchor_terms` with an explanation; never add a generic name or arbitrary word just to increase score. A failed patch changes no assignments, stale patches are refused, and `APPLIED_PENDING_REVIEW` is not final acceptance. For affected sources with existing secondary routes, use the original explicit `allowed_repair_writes` repair path and sequential edits; preserve unrelated routes. Reject proposals only with complete valid final judgments and explicit rejection in `optional_rejection_review_file`. Do not claim a move occurred merely in prose. Changed excerpts still require current-fingerprint review before publication.

When only a small final-review tail remains, the controller may combine pending rows from several original chunks into one bounded `compacted_pending_tail` input. Read the current input once and edit its matching submission; do not reopen completed original chunks. Canonical inputs, per-item fingerprints, accepted judgments and validation gates remain unchanged.

Never run two controller commands against one workspace simultaneously. Never reuse reviews from another workspace or an older fingerprint.
For new workspaces, the controller saves `run/initial_script_cluster_snapshot.json` after the first actual script clustering and before any per-item AI assignment override. It preserves byte-exact input definitions/configuration/materials and script groups, selected passages and doubts for later human comparison. This file is an immutable audit artifact, not a worker input, accepted judgment, final report or timing guarantee. Do not edit it or reuse it to supply another run's answers. Legacy workspaces without an initial snapshot are not retroactively relabeled as having one; any reconstruction must be explicitly called a replay.
When one action fails twice with the same input fingerprint, the controller stops further retries. Read the latest failure file and change only the reported review or input; repeated `advance` calls cannot repair unchanged data.

For native collection, execute the returned `collect_command` including `--as-file`, then Read the complete `collect_result_file`. Its immutable UTF-8 feedback includes every exact error and repair command; the terminal prints only an ASCII locator. Do not capture/recode stdout with PowerShell or infer completion from existing blank answer files. Repair only the listed missing/error entries, preserve successful workers, and collect again. This reading transport never approves an answer or bypasses ordinary validation; legacy direct-output callers remain supported.

## Semantic stages

Read [workflow.md](workflow.md), [contracts.md](contracts.md), and [review-rubric.md](review-rubric.md) when completing their corresponding reviews.

1. **Period configuration.** Set `serial_drama` for continuously updated drama and `episodic_variety` for weekly variety. Put exact work names in `strong_terms`, ambiguous bare titles in `weak_terms`, people and roles in `auxiliary_terms`, and other works in `comparison_terms`. Old reports, cards, old clusters, and expected sample counts must not enter the run.
2. **Source review.** Review only the generated compact queue. Decide `retain_core`, `retain_consensus`, or `exclude`, and choose `evidence_candidate_index` whenever possible. Retained sources need no repeated prose reason; when excluding for the displayed auto_reason, the controller reuses it after your explicit exclude decision; write a new reason only when your judgment differs. Never agree without reading. Exact text copies share one representative decision. For variety, retain the latest episode, a genuinely prominent new topic from the immediately previous episode, or current program-level discussion.
3. **Link and copy checks.** The controller checks links only for sources still eligible after content review and reuses recent definitive results from the project-local cache. Delete only a 404 or 410 reproduced by two GET requests. Login walls, 401/403/429, anti-bot responses, 5xx, DNS failures, and timeouts are indeterminate and are not cached as proof. Exact and high-confidence same-copy families are merged deterministically. Medium-similarity pairs remain independent by default, because similar viewpoints from different authors are useful evidence.
4. **Cluster discovery.** Read every `readable_input_files` entry in order with the host file reader, then derive current-period positive, objective, and negative clusters. These content-addressed UTF-8 JSON views preserve every field and all 180 stance- and channel-stratified passages from canonical `input_files`; they split by display size, not selection or importance. Follow `reading_instruction` for long strings and continue by line offset if a single large item needs pagination. Do not print the seed through shell commands or create conversion scripts. All retained sources are still assigned and coverage-checked later. Each non-background cluster needs a concise set of aspect-bearing `required_any` terms, including needed synonyms; work names, person names, “剧情”, “热度”, or generic praise cannot be the routing basis. If many sources fail aspect alignment, the controller returns `cluster_definition_repair`: repair missing viewpoints or synonym terms before writing individual overrides.
5. **Assignment repair.** For the current residual chunk, align target work, aspect, local stance, and verbatim passage. Submit only the IDs in the current template; the controller merges prior rounds through its ledger. An item still present after an override means that override failed and must change. A valid opinion should move to a fitting cluster or a newly evidenced cluster. Use `__exclude__` only for evidenced cross-work mismatch, out-of-scope text, no reportable viewpoint, abusive noise, pure promotion, or corrupt duplication.
6. **Cluster-set review.** Review titles, stance purity, period or episode scope, source role, and granularity from representative members. Return one decision, an empty `issues` list when passed, and one reason; scripts own counts, range status, fingerprints, and mechanical confirmations. When actual members are misrouted, use `operator_contract.member_repair` directly with their current IDs: prepare, read the scoped evidence, edit only the returned patch, apply, then advance. Never mutate definitions merely to unlock the override file; that invalidates prior bindings. Only a genuinely unsupported cluster claim/boundary uses the explicit `definition_repair` path. Objective clusters may contain neutral facts, observations, or neutral summaries of opinion distribution; individual positive and negative evaluations belong in their matching stance clusters. A normal period usually has 9–16 one-level clusters, but this is a review range, never a quota.
7. **Final excerpt review.** The script first ranks locally complete same-segment aspect-and-stance candidates ahead of weaker extracts, then automatically accepts only complete 70–150-character passages where one local segment contains both a concrete aspect and one unambiguous stance. Separate sentences may still form a valid excerpt, but AI must confirm their semantic relation. Broad retrieval words such as 群像、竞争、特效、质感, mixed, contrastive, short, promotional, cross-work, target-ambiguous and otherwise uncertain items remain in the AI `input_file`; do not reopen `excerpt_semantic_auto_accepted.jsonl`. For AI items, ordinary submissions need only decision=keep and evidence_candidate_index. Keep declares that you have read and confirmed the target, core aspect, local stance, and completeness; the controller fills the matching fingerprint, stance and confirmation fields. Use separate aspect/stance indexes only when necessary. Blank decisions never pass. Existing verbose reviews remain supported. A prefilled reason is needed only for ambiguity such as cross-work attribution or a disputed lexical hint; one concrete sentence is enough. When `cluster_claim_review_required` is true, confirm the core viewpoint. Each sample need not cover every parallel detail in the title; narrow an over-specific title rather than discard valid opinions. A roster, material announcement, brand action, or generic mention of a broad term does not support a narrower claim. When target review is flagged, confirm that the anchor and current opinion refer to the same work; a work name appearing only in a tag, roster, or roundup does not pass. Re-excerpt or reassign a repairable item before dropping it. No cluster is dropped because it has only one or two samples, and unchanged item fingerprints keep their completed reviews after a targeted repair.
8. **Render and verify.** Scripts remove hashtags, mentions, emoji or platform emotes, links, and share boilerplate while preserving raw positions. Positive, objective, and negative evidence must stay separate. The controller stages the page, validates data equality, provenance, unresolved queues, link policy, and offline assets, then atomically publishes the official HTML.

## Domain rules

- Source admission requires a target-work connection plus a usable judgment or relevant factual context. Person names are routing helpers and cannot admit or cluster a source by themselves.
- A mixed article may contribute separate positive and negative passages when each passage is complete, non-overlapping, and locally aligned. A reversal elsewhere in the article does not invalidate a usable passage.
- A negated local sentiment (including double negation or a future condition) cannot auto-confirm polarity from the embedded cue. On `negated_sentiment_requires_review`, read the actual judgment and explicitly set the fitting `passage_stance`; never invert to praise or exclude the source mechanically. This is a scoped uncertainty, not a finding that the opinion is invalid.
- Preserve independent authors who express the same opinion. Deduplicate actual reposts, copied manuscripts, and clear rewrites of one manuscript.
- Mainstream status comes from exact reviewed account aliases, verified parent entities, or verified first-party domains in `assets/media_subject_registry.json`. Certification is supporting evidence only. Authority changes display priority, not relevance or truth.
- Explicit AI-generation disclosures, leaked drafting prompts, and model meta-output are source-level exclusions. Ordinary discussion about AI is allowed.
- Drama uses the continuous monitoring window. Variety centers the latest episode; the prior episode enters only for a newly prominent topic during the current week.
- Short video without usable ASR is excluded from text evidence. Pure schedules, cast profiles, plot summaries, giveaways, ticketing, QR codes, and campaign instructions cannot support a viewpoint. A source containing a valid opinion may remain, but its displayed excerpt must omit purchase, lottery, follow, and participation instructions.
- The page is a self-contained local HTML file with no remote assets and no active `*.woa.com` links. A cumulative workbench is built only with the controller's `merge` command from verified standalone pages.

## Division of work

During native background review, actively wait at most45 seconds via host TaskOutput or the returned `wait_command`; never end the turn just to wait passively for notifications. On each timeout, inspect the pending native task IDs using host status. A timeout or old output file is not failure. Only an explicit terminal failure/aborted/connection error, with the old writer confirmed stopped, permits retrying that failed worker in this same inherited-model window (at most2 confirmed-failure retries). Read its current answer first and preserve completed entries. Do not rerun successful workers, change networking/model settings, or bypass collect. At the retry limit preserve checkpoints and report the block.

Scripts own extraction, stable IDs, deterministic cleanup, hard AI-draft patterns, reviewed media lookup, safe link checks, exact-copy handling, scoring, fingerprints, evidence indexing and backfill, source-position checks, HTML generation, and verification. AI owns ambiguous source relevance, irony and mixed stance, current-period cluster discovery, residual assignment, cluster-set judgment, and final excerpt semantics.

Completion requires `workflow_status.json: COMPLETE`, `render_summary.json: RENDERED`, `verification.json: PASS`, no unresolved review queues, exact HTML/dataset equality, and a visual inspection. Report final sample count and final one-level cluster count separately.

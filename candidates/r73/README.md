# r73候选：演技观点收敛与负面信源排序

基于已发布的r72分支开发，尚未推送。2026-10-09 已用同一批《金色》原始 Excel 分别完成 GLM 和 DeepSeek 独立 WorkBuddy 实跑；《兰香如故》原表仍未找到。

## 改动

- 正面、客观中以演员演技、表演或角色演绎为核心的观点合计最多2组；不能按演员/角色逐人拆。答卷新增`performance_focus`布尔值，发现阶段校验上限及明显的表演标题标注；单独谈动作设计或实拍打戏不因此算演员表演。正面至少10组仍是硬门槛，需由其他有据且不同的方向补足，不得拆近义表演观点凑数。
- 负面观点在相近相关性分数内优先微博、小红书，其次公众号、今日头条、境内新闻；送审前和最终展示均采用该顺序。正面、客观的媒体优先规则维持r72做法。不新增评论数据，不凭渠道直接认定观点有效。
- 保留r72的原文溯源、AI稿排除、摘录长度、自适应补样和离线HTML模板。

## 问题定位

用户分享的《兰香如故》工作台共14组，其中正面第6—8组分别围绕谭松韵、刘学义和配角表演，属于按演员拆分；第9组为反串造型与仪态，需按具体原文判断归表演还是视觉造型，不应机械再立一个演技近义组。该工作台负面3组的展示样本为6条公众文章、2条境内新闻，没有微博或小红书。分享页只含入选样本，无法判断未入选的社交评论是否够长、够贴题；因此当前不增加原始采样。

## 验证状态

- Python语法检查与`tests/test_r73_feedback.py`通过。定向检查覆盖第三个表演簇被拦截、正面10组下限、负面同分信源顺序，以及高相关性候选不被渠道顺序越级覆盖。
- 同一批《金色》原表的离线`prepare`约7秒，r73与r72形成完全相同的136条观点发现代表摘录。曾试过在粗分阶段提前提权社交渠道，但抽出的若干“负向词”帖实际是剧宣或玩笑；因此本候选把渠道优先限制在AI确定负面观点之后。用r72已形成的三个负面候选池离线重排，前10条中社会渠道只在一组由0增至1；该条为玩笑式“吐槽”，末端AI仍须拒绝，不应把渠道变化当成质量提升。
- 初次 GLM 实跑因 WorkBuddy CLI 独立登录返回 401，模型未开始；用户通过腾讯 iOA 登录 CLI 后，重新从新工作区实跑。该初次 401 不计作质量或用时验证。
- GLM-5.3-Flash：完整进程 25分08秒，工作台 51 条、正13/客0/负2组，演技/表演相关2组，编辑完成；但一个原生审样包停滞，10条候选最终未审，`finish_reason=PENDING_WAVE_NO_PROGRESS_300_SECONDS`。因此只能算限时发布，**不能算审样完整验收**。负面8条中小红书1条、微博0条。
- DeepSeek-V4.1-Flash：完整进程 22分14秒，工作台128条、正11/客1/负3组，演技/表演相关2组，待审0，编辑完成，结构校验通过，冻结Skill未变；达到本轮30分钟完整交付门槛。负面19条中微博、小红书均为0。
- 同批原表的r72对照为GLM 111条、DeepSeek 135条；r73的GLM因单包停滞只能保留51条，DeepSeek为128条。不同模型分组和审样有波动，这些数字不能单独归因于本轮信源或聚类改动。
- 两轮179条展示摘录已逐条回查原始Excel单元格及截取位置，未发现不一致。三项脚本级回归检查分别通过：`test_issue_regressions.py`、`test_r73_feedback.py`、`test_workflow_controller.py`。
- 实跑后仅收紧了本地候选的表演标题识别边界：去掉笼统的“打戏”硬拦截，保留明确的演员动作表演措辞；两轮实跑用的完整Skill快照未包含这项小修，需以定向回归和下次实跑继续观察。
- **负面来源效果仍有限。** 候选池中虽有微博、小红书，抽查靠前的社交候选，多为剧宣、正面评价、仅描述改编事实或幕后玩笑，不能仅凭渠道优先当作负面。r73 已在相关性相近的负面候选间提权社交评论，但此批最热原表不足以稳定产出社交负面样本；按用户本轮要求，未增加微博评论数据。
- 《兰香如故》9月24日原始Excel未在本机找到；该分享工作台不能替代原表重跑。

# 影视简报传播特征

默认填充[可编辑的Word模板](assets/propagation-template.docx)生成report.docx，内容为影视简报“一、总体传播特征”的文字、趋势图和情感图。固定句式、加粗和段落版式由模板控制。程序负责数值、来源、单位和图文一致，AI只填写话题关联、讨论话题、节点解释、情感概述和标题所需的审阅字段。只读输入文件，不改动已有观点清洗skill。

## 输入各有用途

| 材料 | 唯一职责 |
| --- | --- |
| 本期热度表的日趋势、小时趋势 | 更新趋势，计算传播总量、峰值，读取截止时间 |
| 上期趋势表或本skill输出的trend.json，可选 | 续报保留历史数据 |
| 微博热搜表 | 相关话题筛选、阅读量前三和合计 |
| 本期清洗流程生成并完成审核的第二部分观点稿 | 提炼情感观点；占比另按明确的方法和来源提供，不能按选编观点计数 |
| 公开搜索核验的节点日传播证据，可补充本地样本 | 解释最新节点，不替代Excel统计 |
| 上期报告，可选 | 辨认已分析的节点，不当成本期观点证据 |

“6条趋势记录”“6篇样本”“累计传播量”是不同指标；每条趋势记录内可能包含数十万传播量。没有检查热度字段和统计范围，不能把记录数当成传播量，也不能凭返回列表判断完整任务仅有一种数据维度。

日常运行承接 film-brief-cleaning 的本期交付。配置 `cleaning_handoff` 后，prepare 自动校验二期完成状态、作品、期次及交付文件，读取第二部分正文和工作台已审原文。有独立样本情感统计时，可配 `sentiment_statistics` 导入计数和分母。有需要时，build、verify 后运行 assemble 交付两部分合并的 Word。人工基准稿用于版式、措辞参考或明确指定的复现验证。具体交接和缺失情感类别处理见[清洗流程交接](references/cleaning-handoff.md)。

## 运行

在 WorkBuddy 本地任务中可以使用同一个技能包，按任务需要选定 GLM-5.3-Flash、DeepSeek V4.1 Flash 或正式版 Hy4。模型只填写审阅字段，Python 脚本读取 Excel、排序求和、制图、套 Word 模板并验收。换模型时为本次输入新建独立工作区，避免复用其他模型的审阅答案。见[WorkBuddy 运行与验收](references/workbuddy.md)。

使用当前环境的真实Python解释器；依赖见requirements.txt。先读[输入契约](references/input-contract.md)，根据用户文件写本次config.json。相对文件路径相对于config.json；工作区必须是本次新建目录。

```text
python scripts/propagation.py prepare --config <config.json> --workspace <本次工作区>
```

读取生成的review_packet.json和review.json，按[语义审阅规则](references/review-rules.md)填写review.json。不要用示例报告预置正确答案，不要用演员名字自动判定所有相关话题；判断不明的项可标uncertain，输出会如实保持待核状态。

```text
python scripts/propagation.py build --workspace <本次工作区>
python scripts/propagation.py verify --workspace <本次工作区>
```

使用 `cleaning_handoff` 时，继续运行 `python scripts/propagation.py assemble --workspace <本次工作区>`。合稿核对记录保留二期的原始审核状态，AI终审试稿须等待分析师确认。

节点先按[曲线选点规则](references/node-selection.md)确定日期及曲线位置，再按[公开搜索规则](references/node-search.md)先查节点日的讨论或传播，再回查相关事件，并学习[人工稿写法](references/node-style.md)的叙述层级和衔接。以“日期或传播阶段＋有据原因＋热度变化”为主线，热度句按曲线情形优先使用写法参考中的人工稿常用表达；区分升温、周期峰值、第二轮高峰、高位维持和回升，不统一替换成同一句结尾。峰值可以提，由程序核实整个滚动统计周期；单日传播量按需添加，默认不为每个节点报数。节点summary通常25—55字、最多60字；补日期和统计后完整节点通常30—80字、最多90字，含标点、不计空白。先合并同类动作再删无关细节，保留主要因素，不硬截字。缺证节点留空，不用数字补位。

## 固定业务口径

- 首报直接采用本期日趋势；续报以提供的上期历史为底，仅替换报告前一日及当日。缺值不能补零，日期重复不能随意相加；更早日期的回溯修订必须由用户另行指定。
- 截止时间取本期小时趋势日期字段最后一个非空值，并检查时间顺序。累计传播量取更新后日趋势之和；不使用另一窗口的汇总页替代。万保留1位小数，达到亿时用亿保留2位，采用十进制四舍五入。
- 相关话题先作语义取舍，再精确筛选微博热搜榜，按阅读量（万）取前三，并对该榜全部纳入话题求和。其他榜单不混入求和。不同榜单中同名话题不会重复计入该榜；该榜自身出现重复标题时先处理数据冲突。
- 电视剧、网络剧默认概括3个主要话题类别，以四字短语为主，允许“云包场”“剧集服化道”等必要的三字、五字常用词。类别简短、层级一致、尽量不重叠，依据本期材料选取；不足3类时保留待补，不凑数。正文用“网民围绕……等话题展开讨论”，整体加粗类别列表。综艺仍按本期材料概括至少3类。具体写法见[话题规则](references/review-rules.md#话题)。热搜统计窗口与导出快照写入核对记录，不能从晚于报告的快照倒推出报告截止时阅读量。
- 节点默认通过公开网络搜索归纳主要推动因素。面向业务的节点段优先写有证据的正面亮点、事实性宣发和中性讨论。负面评价留给观点概述或风险研判，只有负面材料时留待补证。数字及走势只取Excel。续报仅解释上期已分析日期之后的新节点。通常选一两类有据因素，必要时可保留第三类；不删成空话、不罗列活动流水账。按理解需要保留少量有据人物、物料或时刻；不一律禁止细节。学习人工稿的自然叙述，不移植历史事件；不写取证过程或无依据的判断。程序核实后同时补入周期峰值表述和该日传播量，万保留1位、亿保留2位。其余节点仅在include_daily_volume=true时添加单日量。
- 情感输入分provided（明确给定）、editorial_estimate（观点稿研判）、measured（样本计数）三种。简报正文和图的负面比例须在5%–10%之间，含两端，三类合计100%。编辑研判超范围须重新审阅；给定或实测比例超范围时原值留在核对记录，情感正文及图暂缺。可基于本期观点另填符合区间的编辑研判并说明依据。独立样本统计保留原始计数和范围。
- 电视剧、网络剧情感观点的默认衔接为正面“舆论主要肯定”，中立“舆论热议／关注／分析”，负面占比较低时“少量舆论认为／吐槽”；按观点含义选择动词，范围限定须符合本期占比。衔接词写入完整观点句，由模板填入占比后，详见[情感规则](references/review-rules.md#情感)。
- 情感概述默认选取正面3—4个、中立1—2个、负面2—3个独立观点，每类合成一句简短概述。按意思计数，同义合并；材料不足时少写并记录原因，不凑数。保留评价对象及具体判断，省去例子和延伸说理；选取数量不用于测算占比。
- 一级标题固定以“一、总体传播特征：”开头，整条不超过50字。电视剧、网络剧默认采用“两类推动因素＋热度判断＋积极正面声音占据主流”，具体选词见[标题规则](references/review-rules.md#标题与审阅结果)。根据本期节点、话题、曲线和情感依据填入内容，报告期数辅助识别传播阶段。

## 折线图固定模板

图表格式以assets/trend-style.json及无数据底版为基准，不能只保持近似配色后自由重画。固定画布、图框尺寸、标题字重、透明背景、灰色网格与两端圆点、分类轴半格留白、无千位逗号的刻度、首尾数据点圆点、起点与峰值标签、底部线段圆点图例。不得额外标注末日数值或给每个日期加点。

情感图按sentiment-style.json固定版式，每次根据本期有依据的占比重画，图框宽高固定。审定给定比例沿用“结合大数据分析舆论情感倾向看”，样本计数写明样本范围，编辑研判用“结合本期舆论观点，按简报口径研判”并注明“约”。详细方法及出处留在核对记录，图内沿用基准标题。

所有图表每次都从本期输入重新绘制，即使数据恰与人工稿相同也不复制原图。内置模板只保留通用网格、图例、配色和尺寸；作品名、日期、数值、曲线及情感扇区全部由程序绘制。日常生产不需要人工成稿，也不能用它作为缺证回填来源。chart_style.json记录generated_from_input、实际数据绑定及图像哈希；固定版式不等于与人工图片逐像素相等。

## 节点取证方式

默认使用[公开搜索](references/node-search.md)，无需轻云屿海权限。后台选证与短句修订都会加载[人工稿写法参考](references/node-style.md)；模型自行组织原因与走势，程序不重写为固定结尾。先选有据因素、再学习写法，样例不是本期事件或统计依据。模型身份、每阶段原稿及截断记录留存；超时或缺证保持draft，不以其他模型或历史稿填空。网页读取须按[权限配置](references/workbuddy.md#后台节点搜索的网页读取权限)加载本任务允许规则，以实际读取成功为准。

本地样本仍兼容。approved_mcp仅用于兼容已有合法输入；只有用户另行明确要求且当前环境确有获准企业工具时才考虑MCP，不作为默认步骤。禁止通过浏览器、HTTP或搜索代理访问、探测ydata.woa.com及其子域。

实际搜索就记搜索取证，不声称点击屿海波峰。趋势记录数、返回样本数和传播量分别保存，不能混用。

## 输出和完成条件

deliverables/内主文件为report.docx，另有同文的report.txt、两张PNG及SVG和下期可续用的trend.json。核对说明、时间口径和统计依据单独保存在report.html及metrics.json，Word正文不放核对附录。review_packet.json只供审阅。以后每期直接使用内置Word模板，只输入本期原始数据及上游生成结果。reference_report仅保留为用户明确要求更换版式时的兼容选项，日常运行留空；不要求提供本期人工稿。

默认交付Word，发出前通过后台文档渲染工具生成页面预览并检查每一页。检查图表可读性、图文顺序、分页、标题和微博话题加粗。分页检查不得启动或操纵Word等桌面窗口，不发送键鼠输入、不切换用户窗口；只有用户明确要求界面操作时才例外。后台渲染工具不可用时可使用独立的无界面转换库；试用转换器生成的标记只留在内部预览，不得写回交付Word。记录实际渲染引擎及影响分页判断的限制；若仍不可预览，保留Word并明确说明未完成排版验收，不能用HTML或结构校验冒充分页检查。其他附件仅按需要提供。

可选后台检查入口：`python scripts/check_layout.py --docx <report.docx> --output-dir <内部预览目录>`。依赖独立安装的aspose-words、pdf2image、pypdf和当前环境提供的Poppler；不影响生成Word所需的基础依赖。没有有效许可证时预览保留评估标记，不能将其作为对外PDF。脚本只生成预览及layout_check.json；逐页打开图片确认后，再据实际结果记录visual_review。此脚本不调用桌面Word，也不操作用户界面。

verify必须确认源文件未变、图文与统计一致、所有输出哈希有效、review.json仍与构建时一致。打开HTML检查字体、图表、标题和待核说明。状态complete表示本次各项已有审阅及依据；draft表示存在明确列出的待核或缺证。verify通过不等于数据已经完整，不把draft称为正式终稿。

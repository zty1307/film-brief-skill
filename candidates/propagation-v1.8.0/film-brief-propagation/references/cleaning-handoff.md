# 清洗流程与传播特征交接

## 每期怎么跑

1. 用本期原始文章和帖子导出运行 `film-brief-cleaning`。生成工作台后，可以自动选材、人工选择后继续，或只交工作台。第一部分可以先从热度表和热搜表准备数据。要接成整份 Word，二期须完成选材、写稿及终审，产出 `主要舆论观点.docx` 和交付清单。
2. 用 `film-brief-propagation` 读取同期期次的热度、热搜和下面的二期交付配置。续报时，上期趋势负责滚动统计，上期交付 Word 负责二期跨日对照。公开搜索负责补节点成因。
3. 运行 `prepare` 后，审阅话题、节点及情感概述。正文优先引用二期本期观点段落，个别类别可补工作台已审摘录或独立分类明细中的真实原文。估算或给定比例仍按各自口径处理。
4. 运行 `build`、`verify`、`assemble`。在 `deliverables` 中得到 `合稿.docx`、`合稿核对.json`，以及原来的第一部分及数据附件。合稿保留二期正文、配图、附录中的样本链接。核对记录保留源文件哈希和二期审核身份。下一期可把实际交付的合稿作为二期历史 Word，同时把本期 `trend.json` 作为传播趋势输入。

脚本通过现有落盘产物接力。工作台生成后仍可选择交付方式和选材方式。第一部分运行时不改写二期工作区。

## 配置二期交付

```json
{
  "cleaning_handoff": {
    "workspace": "本期二期输出/automatic",
    "issue_date": "2026-10-25",
    "sample_window": {
      "start": "2026-10-24 22:00:00",
      "end": "2026-10-25 11:27:59"
    }
  }
}
```

把此片段并入当期 config，同时省略手工的 `opinions` 项。workspace 指向实际含 `workflow_status.json` 的目录。脚本检查 `COMPLETE`、作品、两份清单中的审核状态，以及 Word、工作台（如交付）和已审数据集的哈希。期次须与热度表截止日期相同。旧清单缺少期次字段时，以样本导出窗口的结束日期确认期次。所用原始文件名含标准导出窗口时校验窗口至分钟，否则通过配置传入核对过的窗口，并在交付记录中说明其依据。

导出窗口指样本表的检索范围。二期样本的首次发布时间可能更早。若另外做情感统计，可按明确的发文时间和入样规则筛选，并记录实际分母。

`AI_PREVIEW` 是已通过二期自动终审的试稿状态。合稿保留该状态。工作台中纯资讯背景可以帮助了解议题，情感概述中的中立项要有真实的中性讨论作为依据。材料不足时，先回看本期已审原文，仍缺证再保留缺项。

如果二期在已交付 Word 上只更新了主题图，并独立完成了版面检查，可在 `cleaning_handoff` 下增加 `"chart_revision": {"path": "修正版.docx", "layout_receipt": "word_qa/receipt.json"}`。合稿仍保留原交付记录。脚本核验修正版哈希、分页验收、Word 中的实际改动，只接受单张图及其高度变化。正文、链接或其他附件有改动时，应以二期重新交付的成套文件为输入。

## 配置独立情感统计

二期稿回答“舆论在肯定、讨论或批评什么”。二期主题分布图按所选来源的观点主题分组。第一部分的情感比例按独立给定、样本统计或编辑估算的口径确定。

```json
{
  "sentiment_method": "measured",
  "sentiment_statistics": {
    "result": "本期情感统计/统计结果.json",
    "validation": "本期情感统计/验收记录.json",
    "details": "本期情感统计/逐条分类明细.csv",
    "evidence_ids": ["本期分类明细中的实际样本ID"]
  }
}
```

当前自动接口支持共用二期原始导出表的分类统计。脚本校验统计结果、验收记录的通过项、样本窗口及原表哈希，写入三类计数和分母。若已选定需要补证的样本，可填可选的 `details` 和 `evidence_ids`。未配置独立统计时，依照输入契约提供 `provided`、`editorial_estimate` 或其他有明确来源的 `measured` 结果。也可以暂留比例、正文和图，先交明确标记的试稿。

样本统计须保留覆盖范围。负面超过业务经验范围时保留原值、交分析师确认。时间窗、待核项和统计来源写入核对记录，Word 只保留读者理解比例所需的样本范围。

# 在 WorkBuddy 运行影视简报传播特征

从技能管理上传技能 ZIP，选择能读取源 Excel 和 Word 的本地任务。使用指定模型发起对话，并在三模型对照测试时固定模型、输入和配置。模型列表由当前客户端提供，命令行可用 `codebuddy --help` 核对。2026-11-09 本机可见的模型 ID 如下。

| 界面模型 | 本机命令行 ID |
| --- | --- |
| GLM-5.3-Flash | `glm-5.3-flash-ioa` |
| DeepSeek V4.1 Flash | `deepseek-v4.1-flash` |
| Hy4 正式版 | `hy4std` |

在当前本地任务的终端确认 Python 3.10+ 可用，且能导入 openpyxl、PIL 和 docx。缺少依赖时使用当前环境适用的 Python 和包安装方式，依赖清单在 requirements.txt。不同机器重绘图表时使用固定模板所需的字体。

## 后台节点搜索的网页读取权限

在用户已授权公开搜索及正文读取的任务中，通过CLI的`--settings`加载本技能的[节点搜索配置](../assets/node-search-settings.json)。该配置允许WebSearch和WebFetch，禁止抓取屿海域名；只影响本次进程，不修改全局设置、不关闭全部权限检查。已有上层deny仍优先，不能删除企业策略来强行放行。

```text
codebuddy --print --model <本次模型ID> --settings <技能目录>/assets/node-search-settings.json --tools WebSearch,WebFetch --allowedTools WebSearch WebFetch --strict-mcp-config --permission-mode dontAsk --output-format stream-json
```

通过stdin传入本期作品、Excel节点日期与走势及node-search.md规则。每次使用新会话、新输出目录，保存完整工具调用日志。在当前Windows WorkBuddy版本实测中，单用`--allowedTools`仍遇到WebFetch非交互拒绝；显式加载上述settings文件后可以读取正文。不要把`dontAsk`理解为自动批准，它只会拒绝尚未获准的请求。升级客户端后先做一次公开网页读取验证，再进行业务运行。

也可直接使用技能的后台入口，自动加载同一授权文件并保留取证日志：

```text
python scripts/search_nodes.py --model <模型ID> --trend <临时工作区>/review_packet.json --output <全新搜索目录> --cli <codebuddy入口> --node <node可执行文件>
```

`--cli`可为可执行的codebuddy命令；只有它是JavaScript入口时才需要`--node`。`--trend`同时支持已有trend.json；读取review_packet时只提取作品、截止时间和Excel趋势，不把其中的观点稿、历史答案或本地样本交给模型。续报加`--previous-nodes-through YYYY-MM-DD`排除已分析日期。

入口默认采用[分阶段限量流程](node-search.md)：同一模型串行处理各节点，搜索最长150秒，证据选择与成稿合并为一个短请求、每次最长120秒，Hy4为180秒；检索配额到达后不再等待长总结。`--timeout`可进一步缩短阶段上限；无模型自动降级。每个日期目录下的search、write目录分别保存events.jsonl、原稿、执行时间和模型身份；完整修订另存write-repair，只有句子不合格时用summary-repair作短请求修订。source-gate.json记录程序初筛，review.json及review-repair.json记录原文、因素和句子检查。顶层answer.json、node_samples.json、nodes.json、search-audit.json只输出已通过证据与压缩检查的结果；缺证或超时节点留空，状态draft，进程返回非零。

节点summary通常25—55字、最多60字，完整节点通常30—80字、最多90字（含标点，不计空白）。以一句为主，无最低字数门槛。每次选证成稿及短句修订都会读取node-style.md学习9篇人工稿归纳的写法；不是模型训练或记忆更新。通常选一两类原因，必要时可保留第三类；关键细节按需要保留，正文自然衔接热度。selected-factors.json及retained_factors保留对应关系，语义支持仍需审阅。

已有运行检索成功而成稿失败时，可加`--resume-search <该模型的原运行目录>`，并使用新输出目录。程序验证原取证记录的模型身份，只复用该模型自己的实际工具返回，不接收人工整理包或其他模型的证据。search-resume.json保留来源；这属于恢复原取证，不宣称重新搜索。没有原始工具记录或模型不一致时拒绝复用。

断点恢复还要求作品和截止范围一致，并比对缓存正文与原始WebFetch返回。整体运行默认最多600秒，`--timeout`设置整体上限，各阶段也不能超过剩余时间；已完成节点会保留，未完成节点不会用旧稿填空。

时间原文与摘录的程序匹配只清理Markdown链接、图片格式和全半角，不改变日期或语义。原始工具内容完整留存；交接只收实际读取且时间可核验的证据。较早的事件须有节点日仍在传播的依据，来源超期或摘录不实均不能交接。`--single-session`仅兼容旧的单会话取证，不作为日常默认；用`--audit-existing`检查旧日志时同时提供`--trend`，否则不能确认截止范围。

内容仍需按节点规则审阅，程序检查通过不等于事实和写法已审定。把合格node_samples.json填入正式config，再新建工作区prepare，并将同次nodes.json的概述和证据ID填入review后build/verify。此入口不代替完整报告生成脚本。

验收必须看WebFetch实际返回正文，不能只看模型声称“读取成功”或退出码为0。权限通过后，个别网站仍可能因反爬、登录或页面下线而不可读；由同一模型改查其他公开来源，证据不足的节点留空。不能为凑齐结果悄悄换成其他模型或人工提供材料。

交互式WorkBuddy任务可通过其权限管理为WebSearch、WebFetch作相同授权；具体入口以当前客户端为准。本段命令行配置的验证不代表已经操作或修改了用户的桌面任务设置。

可粘贴到 WorkBuddy 的任务描述：

观点输入优先使用本期 film-brief-cleaning 完成的第二部分 Word 和对应工作台，按[交接规则](cleaning-handoff.md)检查作品、日期范围、完成状态与来源。下文“审定观点稿”不指必须由人工预先写好的基准报告。当前只支持文件交接，未实现自动串联两个控制器；不得将人工稿复现测试称为原始样本端到端验证。

> 使用「影视简报传播特征」技能。读取我给的本期热度 Excel、上期趋势、微博热搜 Excel 和审定观点稿；节点分析使用全网搜索查找当天事件，不调用轻云屿海MCP。先prepare到临时工作区，读取候选节点和截止时间，再按公开搜索规则检索并核验正文，保存node_samples.json，在全新正式工作区prepare。根据本期 review_packet.json 审阅相关话题、讨论话题、节点、情感和标题，只修改当前工作区的 review.json，保留输入指纹和每条证据 ID。然后执行 build 和 verify，交付生成的 Word。传播量、阅读量排名与总量、图表和排版都由技能脚本完成。全程本地脚本处理文件，不操作桌面窗口。无需屿海 MCP 即可完成有本地输入的步骤。

电视剧、网络剧标题按[标题规则](review-rules.md#标题与审阅结果)默认使用“两类推动因素＋热度判断＋积极正面声音占据主流”。先将两个因素与热度判断压缩至30字以内，再加固定前缀“一、总体传播特征：”和收尾，整条须在50字以内。按本期传播阶段和曲线选择趋势用语，期数仅作辅助。榜单字段直接读源表。构建若报告标题超长或引用有误，只重审报错项并重跑 build，保留其余已填字段。

遇到较长的热搜表，可把审阅拆成每批 20 至 40 条，逐批保存带 ID 的判断和依据。讨论话题和标题、节点解释、情感概述可以分开填写。合并后检查每条话题恰好出现一次，话题、节点和观点引用均来自本期。模型超时后保留通过校验的批次，只续跑缺失或报错的批次。

填写电视剧、网络剧的directions时，默认3个简短话题类别，以四字为主；每类引用本期已纳入话题，材料不足时留待核，正文整体加粗类别列表。节点写作学习[人工稿写法](node-style.md)，完整summary不硬套结尾；缺证时留空。build输出任何周期峰值时同时补该日传播量。其余节点按include_daily_volume决定是否报量。

验收以本次真实运行记录为准。分别核对选定模型、全新审阅答案、`verify`、Word、图表和源文件一致性。传播总量在相同热度输入下应一致。话题关联判断可能改变阅读量合计和正文；比较时核对取舍依据。给定情感比例是共同输入，模型负责观点归纳。待核项保留在 audit 和运行状态，结果仍为 draft。未经所指定模型实际运行时，记录为未实测。

填写电视剧、网络剧的情感summaries时，把衔接词写入观点句：正面默认“舆论主要肯定”，中立按内容选“舆论热议／关注／分析”，负面占比较低时选“少量舆论认为／吐槽”。不重复类别和占比，不把模板中的固定占比句写进概述。核对三类观点引用后再构建Word；不得把正面肯定或负面批评仅换成“热议”就归入中立。

情感概述默认正面3—4个、中立1—2个、负面2—3个独立观点。先列出选中的观点短语及引用，合并同义，再分别合成一句；材料不足时少写并在审阅记录说明。压缩为具体优点、关注议题、主要问题及担忧，不展开实例或创作道理。只调整情感写法的回归验证可以沿用同一模型已核验的其他审阅字段，但须校验输入指纹与源文件，另建工作区保存新结果，并明确本轮仅重新调用情感概述。

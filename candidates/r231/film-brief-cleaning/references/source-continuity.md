# 来源筛选 观点边界与连续出刊

## 当前来源策略

预处理、观点发现、审样与末端核对合计最多45分钟。确认选材后，另计最多15分钟用于写稿、通读返修和收尾。预算不放松逐字出处、来源、立场、完整原句或独立观点要求。正面至少6个独立实际非空组是硬门槛；不能拆近义观点补数。完整已审工作台仍须满足写稿证据要求才能出稿。

按全文可核证据排除明确AI生成/辅助声明、明确工具答复转贴、模型身份或写稿指令泄漏。向AI工具提问后直接分享“回答不错/如下”的内容也按工具答复排除，不当作独立人工观点。按用户样本格式要求另排除明显`**强调**`或多行星号列表的草稿式来源，审计称“明显草稿格式”，不声称仅凭星号鉴定作者使用AI。正常星级评分、单个乘号、讨论AI行业、仅提到工具名称或明确表示没有使用AI的文章，不因这些字样被排除。

新浪、网易、搜狐来源在相关性/质量接近的候选内降低展示优先级，不一律删除；有独立有效观点时仍可使用。平台识别用来源网址主机、站点字段，不因正文提到这些名字降权，不把微博一并降权。已核实媒体身份仍保留，但平台风险标记单独参与排序。新浪新闻“每日新闻摘／每日新闻摘录”命中账号及平台身份时硬排除；正文提到账号名不是黑名单命中。

## 一个样本只归一个观点

同一期按原表行/来源ID、规范化来源网址、相同全文及相同展示句检查唯一性；同一作者的不同文章不会因此全部合并。同一篇长文选择另一段也不能跨观点使用。先给与核心最匹配的待审观点预约；该路由被AI拒绝后，可在后续波次让另一观点送审，不能一开始永久丢掉另一种可用判断。最终保留项再次全局去重，记录脚本抑制原因；不能把脚本去重说成AI作出了语义拒绝。发布和写稿均有唯一性校验，不靠改变ID规避。

先看当前材料，再区分方面与观点。category为方面导航，core_mechanism为本簇核心评价；同方面、共享证据或判断相近的簇须解释具体区别，包括客观与赞贬的跨类组合。不同演员/角色、不同衣服/妆容若表达同一机制先合并；剧情、演技、服化道不能作为凑数的大杂烩。方面不是必须填满的格子，也不保证自动语义检查能完全消除近义簇，仍须看实际结果。

## 连续三天怎样承接

第二天给第一天已完成工作台，第三天给前两天；用户若有实际采用的成稿编辑计划，再一起提供。仅有工作台时只能知道展示过什么；有指纹匹配的editorial_plan.json才知道实际写过哪些点和样本。

```powershell
<python> -X utf8 scripts/integrated_workflow.py start --source <当天原表目录> --workspace <新工作区> --target <作品名> --history <前一天工作台.html或final_dataset.json> --history-plan <前一天实际采用的editorial_plan.json>
```

重复--history和--history-plan可提供多天。计划必须匹配对应工作台的数据指纹及作品，不能传入人工基准报告或别剧材料。缺少实际计划可省略--history-plan。历史意义对照进入本期同一次观点发现；历史句只参与比较，不当作本期证据。没有历史输入按独立一期处理。

写稿时可直接读取当前工作台的continuity_review，也可明确提供历史比较输入：

```powershell
<python> scripts/report_writing.py prepare --dataset <当天final_dataset.json> --outdir <新写稿目录> --history <前一天final_dataset.json> --history-plan <前一天实际采用的editorial_plan.json>
```

填计划时每点增加至少12字continuity_reason，说明本期新增证据、此前未展开的角度，或为何持续保留；随后按原来的render命令成稿。工作台可从较多独立观点中选择当天重点，但不能拿历史样本补进当天引用。图表、逐字出处和审核状态规则不变。

区别三件事：新来源、旧来源里的新判断、已存在但此前没写的角度。脚本只给来源/样本复用及前稿使用记录，不自动把换样本或换标题判成舆情变化。模型须复核是否真的有新观点；没有变化可以保留核心评价并说明持续关注，不编造升温、发酵或新增争议，不要求三天所有点都不同。没有足够可用角度时明确告知业务，不能通过随机性制造差异。

历史文件只本地解析，来源地址不联网加载，ydata.woa.com及子域始终禁止直接访问。

## 可选：对已有工作台单独评阅

以下period_compare仅用于用户明确要求对已有工作台单独评阅的场景，不是一体化默认步骤。正常连续出刊已在聚类发现阶段比较，不再追加这一轮。单独评阅使用已审展示句，另记耗时，不改原聚类、不再审原表，不回填原运行时间。

```powershell
<python> scripts/period_compare.py prepare --dataset <本期final_dataset.json> --history <前一期workbench.html或final_dataset.json> --outdir <比较工作区>
```

模型只读comparison_input.json，一次写comparison_answer.json：每个本期观点与前期观点是延续、更具体展开、不同方向评价，还是前期未展示的独立角度；理由绑定本期已审candidate_id和原句。必须阅读前期全部展示句，不能只因标题更细就说它前期没有。然后选0—5个有据的daily_focus，不必全部都是新角度，重要延续也可保留。没有实际新重点就填空，不拿边角料凑不同。

```powershell
<python> scripts/period_compare.py collect --outdir <比较工作区>
<python> scripts/report_writing.py prepare --dataset <本期final_dataset.json> --outdir <写稿工作区> --period-comparison <比较工作区/period_comparison.json>
```

脚本输出period_comparison.json与daily_focus.md。写稿输入只承接本期已审样本及比较结论，不带入历史引文。每点continuity_reason解释取材选择；不要求把建议重点全部入稿，不用“首次”“新增争议”“舆情反转”等超出比较范围的断言。前期工作台不等于前期实际报告，缺少实际采用计划时，只能说前期展示过什么，不能声称知道前稿已写或未写。

旧版已发布HTML工作台也可通过--history提供。脚本只解析DATA字面量，不执行脚本或加载来源链接；只有历史HTML时仅统计展示记录，不能声称知道实际成稿用了哪些点。原始工作台的数据版本与当前原表不一致时，比较和实测分别标明，不能当作同输入复现。

比较理由的范围：展示数量有上限，不能据此声称总体声量最多或口碑主面；来源评价不能写成事实已被坐实。比较只针对给定前期材料，不宣称全网首次。脚本校验取材理由中的明确越界说法，不修改来源引文本身；其余语义仍由审稿者核对。规则标记r102-selected-scope-v2。

## 当前默认：在观点发现阶段对照

--history的全部已展示短句、标题和核心机制进入同一次发现包；不输入HTML代码或旧全文，不增加前置模型调用。每簇对照continuing/developed/opposing/unseen_angle并绑定当前E句及匹配历史句；未再保留的前期簇需说明取舍。后期继续使用当前原表，不因历史出现过就硬删本期重要观点。类别换名、换演员或例子不算新判断，不按新增配额拆分。完整工作台才用于下一期。本期聚类后默认直接接写稿，不再重复独立的写稿前比较；独立period_compare仍仅作显式可选的评阅工具。

# r72：影视简报样本清洗 Skill

r72用于生成供人工选材的离线观点工作台，已在GLM-5.3-Flash、DeepSeek-V4.1-Flash及Hy4上完成同一期真实测试。

## 下载和使用

- [直接下载安装包](../../dist/film-brief-cleaning-r72.zip?raw=1)
- [完整Skill源码](film-brief-cleaning/)
- [执行入口](film-brief-cleaning/SKILL.md)
- [文件校验清单](production-manifest.json)

解压后，把完整的`film-brief-cleaning`文件夹交给WorkBuddy加载，提供本期原始Excel目录和剧名即可。Python 3.10+及`requirements.txt`中的openpyxl是运行依赖。默认由`scripts/final_sample_review.py prepare --discover-viewpoints`开始，随后跟随控制器的`next_action/read_now/next_command`。

> 请读取并按本目录film-brief-cleaning/SKILL.md处理我提供的本期原始Excel，生成观点工作台。总墙钟30分钟；未达要求如实说明，不修改Skill或引用旧答案。最终简短报告状态、数量、用时和输出路径。

## 主要变化

- 总观点10—16组、正面至少10组、负面最多3组，每组最多10条；证据不足不凑数。
- 短评至少50字、文章至少70字，上限360字，按清理后的可见文字计数。原始摘录、Excel位置和清理后的展示文字分别保留。
- 在观点发现之前按全文明确声明排除AI稿，不把普通讨论AI的文章误当成生成声明；发布前再次检查来源。
- 根据剩余时间把审样包从最多10条逐级缩小到1条，优先补样本较少的组；最小批次也放不下才收尾。编辑及校验预留300秒，任务关闭预留180秒，不重复相加。
- 送审前跳过整个可选窗口清理后都不够字数的候选；已提交答卷的错误明确进入返修，避免把纠错当成等待。
- 复用已有媒体主体库，在相近匹配分内优先已识别媒体，入选后排在组内前列；主流媒体身份不等于内容自动通过。

## 已知边界

- 这是同一期数据的三次观测，不是跨期稳定成功率或任意数据30分钟保证。外层测试监控执行硬截止；其他宿主仍需可靠的时间和取消机制。
- 媒体优先采用相近匹配分内的排序，匹配分较低的媒体仍可能未被送审。原表本轮识别到13条媒体记录；最终GLM仅1条媒体摘录，DeepSeek 5条、Hy4 6条（后两者各来自2个独立来源）。媒体覆盖仍有提升空间，不能理解为每组都先选足媒体。
- 保留的是人工选材候选，个别题文贴合、立场边界、概括粒度仍需业务复核。不同作者对事实的说法没有通过联网校实，不能将来源自述升级为已确认事实。
- AI仅审展示候选；最后编辑每组最多2条，是有限抽查，不是全部来源或全部展示句二审。候选不足、未通过或预算停止均不得用未审样本补齐。

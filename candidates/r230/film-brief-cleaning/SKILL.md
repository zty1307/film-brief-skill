# 影视观点聚类与写稿 r230

默认先自动聚类并交付已审观点工作台，再让用户选择“我来选材料”或“由你自动选材写稿”。用户在开始时已明确全自动、人工选材或只要工作台，就按原指令执行，不重复提问。写稿只承接工作台已审内容，图表嵌入Word，工作台正面观点先按已审去重样本数排序。图条自上而下按最终正文顺序排列，批评和“其他”遵循 [图表区间规则](references/chart-coverage.md)，文末按 [sample-links.md](references/sample-links.md) 自动附实际引用样本的原文链接；不需要截图。两条分支共用同一个skill与同一套质量规则。

## 工作台完成后的选择节点

按 [writing-choice.md](references/writing-choice.md) 执行。提供工作台链接及控制器handoff_message后，若用户尚未决定选材方式，调用WorkBuddy原生AskUserQuestion，参数用状态中的writing_choice。这是一道单选题，客户端自带自填回答入口，但没有文件上传字段；选择题只负责分流，文件从正常聊天附件发送，不手工增加“其他”选项，不伪造answers。用户可以直接自填“自动写稿，重点关注剧情和服化道”。只问一次；没有回答、跳过或界面关闭时，保留工作台并等待后续明确指令，不替用户选自动、不循环提问或继续写稿。原生工具不可用则用文字给出同样两项并结束本轮回复。

选“我来选材料，稍后发文件”（含同义回答）：结束选择题，展示manual_handoff后结束本轮回复，让聊天框恢复正常收文件。不要把选择题留在等待状态让用户去选材，不循环询问是否已选好。用户在工作台勾选观点和样本，导出后发回同一对话或已安装本skill的新WorkBuddy对话，再由模型自动写稿、通读返修、附链接并交付Word。文件自带观点、样本及出处，不依赖旧对话历史。收到有效选材文件后，即使用户只发文件、没有附带文字，也直接from-selection，不再次询问模式、选点、版式、是否写稿或是否继续。

选“由你自动选材写稿”：以当前工作台的final_dataset.json运行from-workbench，使用新写稿目录及状态中的auto_writing_budget_seconds，不重跑聚类。原工作台回执保留清洗耗时。确认选材方案后，写稿和终审独立计时，最多15分钟。用户等待选择/选材的时间不计入模型运行时间；不得修改原开始时间或旧失败状态。

有自填补充要求时，按实际回答保存UTF-8 JSON `{"requirements":"用户的实际补充要求"}`，接续命令加 `--requirements-file <该JSON>`。脚本把要求传入提纲、正文和终审输入包，避免后续写者丢失。只能在已有证据范围内满足要求；材料不足具体报告，不补原表、不降低证据和终审标准。跨新对话时以新消息或文件中的要求为准，不声称读到了旧对话未携带的补充要求。

## 按输入选择入口

- 输入是原始 Excel：按下方 start 命令聚类，默认完成后停在 `HUMAN_SELECTION_REQUIRED`，交付 `delivery/观点工作台.html`。按上述选择节点询问一次并等待；已明确人工选材时展示导出指示。未获得自动选材的明确选择前，不能替人工自动勾选或继续写稿。
- 输入是本期原始 Excel 和同作品前期已交付 Word：执行 `start`，每份前期 Word 用一次 `--history <前期报告.docx>`。只比较前期已经写入报告的舆论观点，材料不足时允许延续同一核心判断。
- 输入是 `*-写稿选材.json`：直接执行下面的 `from-selection`，不先完整读取选材文件、原表或原工作台。脚本校验并生成精简的 `read_now`；模型只读当前包。完成后交付 `delivery/主要舆论观点.docx`。
- 只有用户明确要求自动从聚类到成稿时，给 start 加 `--auto-write`。已有完整工作台的旧自动写稿入口保留用于明确要求的自动测试。

```powershell
<python> -X utf8 scripts/integrated_workflow.py from-selection --selection <人工导出的写稿选材.json> --workspace <不存在的新写稿目录>
```

人工模式优先执行 [human-selection.md](references/human-selection.md)：段数跟随选点，例如选五个就写五个；非负面每组一段，多个批评汇为唯一末段。不能再套“至少六个正面段”，不能自行增删或拆分人工选点。证据不足说明具体缺口并退回选材。模型只可从选中样本中择优，仍须满足观点成立、独立来源与完整通读要求。工作台与写稿分开计时，工作台最多45分钟，写稿和终审最多15分钟。等人选材的时间不计，跨对话保留工作台原清洗耗时。

## 执行原则

工作台阶段最多45分钟。选材确认后，写稿阶段独立计时，最多15分钟。工作台优先形成8—10个互不交叉且各有至少两条独立有效声音的正面观点，自动成稿模式至少保留6个；人工模式以选点为准；工作台硬下限仍为6个，不靠拆点补足目标范围；材料不足如实说明，不拆近义观点凑数。写稿只读最终工作台，不补原表，不输入人工基准。

模型负责观点、作品指代、态度、证据支持与成稿判断；脚本负责字段、溯源、去重、计时和交付。保留方面与核心判断，仅对风险组合说明区别。证据和审核标准不因提速降低。

所有条件字段和允许值以当前输入包为准。返修使用 `scripts/repair_packets.py` 生成绑定当前答卷的局部任务，模型只提交任务指定的修改；脚本合并并重新执行原校验。未变化的已通过项不重写，原审核指纹不可伪造；模板修复不代表语义通过。不能反复发送同一完整答卷猜测格式。

正文按 [writing.md](references/writing.md) 组织，图表按 [chart-coverage.md](references/chart-coverage.md) 审核；最终由本次模型按 [final-prose-review.md](references/final-prose-review.md) 通读实际成稿，有问题返修后重新复核。通常每段3—4条互补声音，充分时2条；肯定、认可与讨论在前，批评仅一个末段。旧审稿不能复用于改后的稿件。

## 先确定角色

收到某个 input_file/answer_file 包的原生审核者只读该包，按包内规则逐步保存自己的完整答卷，不接管控制器、不读其他包或全量原表、不另起 Agent。以下操作只由接到原始数据任务的主窗口执行，工作区始终只有一个控制器操作者和一个答卷写者。

用户只需开一个 WorkBuddy 主窗口提供文件夹和作品名；原生 Agent 继承当前模型，省略 model 参数，不在 Skill 内启动其他 CLI 或外部模型。

## 一体化入口与预算

先读 [integrated-workflow.md](references/integrated-workflow.md)。使用真实 Python 3.10+，安装本 Skill requirements 中的依赖；不要用 Microsoft Store 占位解释器。

```powershell
<python> -X utf8 scripts/integrated_workflow.py start --source <原表目录> --target <作品名> --workspace <新工作区>
<python> -X utf8 scripts/integrated_workflow.py advance --workspace <工作区>
```

默认工作台2700秒、写稿900秒，分别从各自阶段开始计时。通过 `--cleaning-budget-seconds`、`--writing-budget-seconds` 设置各阶段预算，结果分别报告两个阶段的实际耗时和完成状态。阶段内续跑保留原时钟。

清洗阶段按最近一次内层命令返回的 read_now、next_command 或 handoff 执行，不反复使用旧的外层指令；需要刷新外层状态或清洗结束时执行 resume_command。写稿阶段按 workflow_status.json 的 read_now 和 next_command 执行。正常 ACTION_REQUIRED、REVIEW_REQUIRED 不读脚本实现、不扫描全部工作区、不写辅助程序。只修反馈列出的字段；只有真实 BROKEN 才诊断代码。一个控制器命令若进入后台，先等它结束，再运行下一个。

字段修改后若repair_feedback.unchanged_after_failed_validation为true，说明文件内容实际未变，优先执行该反馈的patch_command并读回核对，不继续猜测字符串替换。字段修改若遇到宿主 Edit 回报成功但校验仍读到旧值，停止重复 Edit。使用本 Skill 的 `patch_answer.py`：先以 Write 保存补丁 JSON `{"changes":[{"path":"/clusters/0/title","expected":"当前原值","value":"模型确定的新值"}]}`，再执行 `<python> -X utf8 scripts/patch_answer.py --workspace <本期工作区> --answer <答卷相对路径> --patch <补丁相对路径>`。脚本要求原值匹配、只修改指定字段、保留指纹，并实际写后读回验证；不生成或代填任何语义判断。原写者仍在提交时不能抢改答卷。新的完整答卷仍可直接 Write；不要为读取报错条目另写临时提取程序，直接读反馈里的 repair_items。

返修工具：原写者结束后执行 `<python> scripts/repair_packets.py prepare --kind review --input <当前审样包> --answer <原答卷> --feedback <反馈JSON> --out <局部任务JSON>`；其他发现/提纲/写稿字段返修用 `--kind fields`。读生成的任务，按answer_schema保存回复，再执行 `<python> scripts/repair_packets.py apply --task <局部任务JSON> --answer <原答卷> --reply <回复JSON>`，然后运行原next_command完整校验。补丁是当前答卷的局部修改，不是新的审核通过凭证。

完整工作台出现后执行 advance；默认交付工作台后询问一次选材方式；用户选自动后从既有工作台接写稿，已在开始时明确--auto-write则直接自动接写稿。未完成审核、证据不合格、末端标题证据核对未完成均不能当完整工作台。TIME_LIMIT_REACHED 只有所有已派审样收齐或合法关闭未审候选、pending=0、结构与溯源通过时，才可进入独立计时的写稿阶段；原超时记录保留。部分结果与 FINAL_TITLE_EVIDENCE_REVIEW_INCOMPLETE 不放行。新任务合法关闭未审候选后，仅实际已审展示数据可继续；不改旧失败记录。

## 先保住工作台，再给人工增加选择

出现六个各有两份候选原话的正面组后立即核对标题、独立证据及组间交叉；候选数本身不算通过。六组真正过审后，脚本在清洗目录保存 ready_workbench。45分钟共用时钟内，只要还有未送审的候选且来得及审核和发布，就继续小批补审。脚本按实际已留样本数从少到多分发，组满十条后停止补该组，并依独立原话争取八至十个正面组。达到目标、经过筛选的未审候选用尽，或剩余时间不足以完成审核与发布时交台。锁定已审观点、样本与原有成段判断。补审只读新样本。同一来源只匹配到一个未满观点时，脚本按实际留样数排序，直接送常规逐条审核。各项原文、具体评价、作品指代、立场、长度、来源和去重要求照常执行，审核通过才可按组追加，最多10条。来源可能落在多个观点或尚未确定归属时，交AI按当前包判断。常规补审与新观点发现交替推进。只有新增观点需要单独核对标题证据及与旧观点的交叉；出现SUPPLEMENT_VIEWPOINTS_REQUIRED时只审new_groups并执行supplement-collect。某组未通过、超时或答卷失效只排除该组的未审增量，已审新增和旧结果仍随工作台交付。

工作台阶段有独立的45分钟预算。交台后选定方式，写稿和终审另外计时，最多15分钟。补审超时或重复返修无法在清洗截止内完成时，先结束本次真实写者，再运行原 integrated_workflow.py advance 加 --use-ready-workbench，使用已有保护快照。最终工作台交付后才询问人工勾选或自动选材。等待用户选择的时间不计机器耗时，两条分支都从该工作台接续。

## 来源均衡与聚类补缺

正面至少6组是最终硬门槛，每组须有两条经末端核对、最终仍展示的独立有效声音。不能用客观或批评补足；自动模式正文仍为6—7段；人工模式正文段数跟随选点，两者不是同一个计数。每组须有独立判断，不逐演员拆近义演技、不把宣传事实包装成好评。

脚本在相近相关性分数内平衡渠道：保留正面/客观已核实媒体优先和负面微博、小红书优先；优先补较少出现的渠道，今日头条同档后置。每轮排序考虑已经留下的渠道。目标是有合格材料时每组覆盖至少两类来源，不设必须使用低质材料的比例配额；头条占多数或单一渠道会记入source_balance_audit；已确认合格的正面组头条过半时，进入有界补缺检查，不靠删掉所有头条或伪造其他渠道改善比例。

来源字段或原文含“作品声明：内容由AI生成”以及明确模型代写答复时，在发现和送审前排除并保留命中证据；适用于所有剧和平台。“个人观点，仅供参考”本身不是AI标识。若声明仅在网页而没有进入原表，离线脚本无法凭空知道，不声称已检查网页声明。

本期出现COVERAGE_REPAIR_REQUIRED时仍属于聚类：只读coverage_repair_input.json，填写coverage_repair_answer.json，再执行repair-collect。首轮重审和补样合计最多12条、增加最多3个确有E原句支持且不交叉的正面观点；新观点和候选仍须走原逐条审样、唯一样本与末端标题核对。补第六组时先给缺一份独立声音的实质观点补证，有两条不同来源的有据候选时同时送审，避免把全部缺口押在一条样本上。首轮后如仍不足且可安排复核，继续小范围补缺。原有逐条判定保留，旧拒绝保留改判审计，原时钟不重置。首轮最多追加30条审核，未派/未审不计通过。硬下限补缺保留完整复核预算，已有合格快照后改用多批增量审查，候选数随可用时间缩小。增量归组包按实际给出的候选编号、原句编号和观点编号提交，脚本绑定原表记录及连续原文窗口。某组的引用或字段有误时，只返修相关候选和组，已经核验能送审的候选先进入逐条审核。作答后预留校验与交台时间。不能以补缺为名开始第二轮全量聚类。

工作台最多45分钟，写稿、通读返修和收尾另计最多15分钟；已明确自动写稿才进入写稿。最终仍不足6个正面组时保留已有工作台并如实报缺口，不能为了“不卡住”降低证据标准。新的补缺只用于本版新启动任务，不改写旧失败结果。

发现输入仅展示原句和来源事实，不展示脚本猜测的正负面/方面标签。社交非批评句仍需按实际内容考虑正面观点。作品指代包可提供向前最多800字内最近剧名所在的连续正文，但不自动判定承接；审核者仍须排除旧作、对象切换和戏外互动，引用只能来自选句窗口。多个选句窗口分别提供自己的指代上下文。

## 本期观点发现

控制器先做原表提取、来源政策、去重、分层召回和本期代表句准备。主窗口完整读当前 viewpoint_discovery_input.json，从本期 E 摘录判断实际观点，按 schema 一次写答卷。seed、路由词和标题证据只能来自本期 E，不能来自历史、基准报告或想象。

每簇一个 category字符串、一个 core_mechanism。category从allowed_categories选一项，不填数组、不自改名称。title_evidence总计1—3条，每个标题分句一条，不是每个seed一条；每条seed_ids最多3个，整条E句支持该分句时可用quote_seed_id由脚本逐字回填，需截取时只填quote_snippet，context不能代替。围绕剧情叙事、人物书写、演员表演、动作、服化道、视听音乐、社会文化价值等实际评价机制归类，不按类别凑数。近义、总括与子例先合并；同方面、共享seed或判断相近的风险对须说明真实区别，包含客观与赞贬跨类。正反评价可以并存，不能用“关注”另装一次相同批评。

正面与客观的演技机制合计最多2组，不能按演员、角色、主演/配角逐人拆近义观点。负面最多3组，保留主要且机制不同的批评。实际总数1—16组；正面至少6个独立组且各有两份最终展示的独立有效声音，不足先做有界补缺，仍不足则标记未达标，不拆观点、不改立场凑数。标题通常24—36字、机器边界12—48字，以判断谓语开头，是一个有本期依据的核心观点。title_evidence 逐字绑定实际 E 原句。

客观簇须区分 neutral_fact 与 opinion_distribution，并核对 seed 实际立场；不能把单边赞誉、批评或未经核实数据说成客观。来源标签、词法分数和填写字段都不表示语义通过。

## 来源与作品指代

正面、客观在相近匹配分内优先已核实主流媒体，再看公众号等；负面优先现有微博、小红书中的真实用户批评，再看公众号、新闻。控制器先从现有原表限量召回相关原句，不依赖原始情感标签；AI 在同一次发现中判断是否真批评。不能把媒体转述当用户直接批评，不增加微博评论行，不以平台身份代替内容判断。

明确 AI 生成/辅助声明、工具答复转贴、模型草稿泄漏、明显双星号或多行星号列表排除；“问了某工具，回答如下/不错”也属于明确工具答复，不当人工评论。普通讨论 AI、提到工具名、星级评分不因关键词排除。新浪新闻“每日新闻摘／每日新闻摘录”黑名单，新浪、网易、搜狐降权；微博不因新浪归属被降权。媒体身份只认本地已核实名单，不猜、不联网。

同一原始样本、同网址或同全文只归一个观点，不改截另一段规避。已审展示句的相同文字、长段近乎逐字重复和相互包含的同稿也去重，包含公众号和转载号；同观点的独立原创表达保留。

原著不是剧版。仅谈小说、作者或书中叙事而没有剧版/改编评价的片段不能借同名剧名放行。比较文章和多作品来源中，选句未在正文点名本期作品时，按包内 work_reference 填 target_scope，用局部承接确认对象；远处剧名、来源标题、单独话题标签不能救援别剧评价。上下文只确认指代，不补观点、态度或字数。歌曲编曲、歌词与演唱评价不能只因出现“成长弧光”就冒充剧作人物书写。

## 跨日比较

同一作品连续出刊时，提交本期原始 Excel 和前期实际交付的 Word 报告（.docx），每份报告通过 `--history <前期报告.docx>` 传入。不同同事只需交接报告文件。脚本只提取「主要舆论观点／舆论观点」正文的段首判断及所引文字，不读传播、风险和样本附件。有历史则比较，首期或无历史输入时独立跑当期。旧工作台 HTML 或 final_dataset.json 仍兼容，也可与相匹配的实际成稿计划配套使用。

历史在同一次观点发现中比较，Word 模式覆盖实际已成文的观点正文，旧工作台兼容模式覆盖实际展示句，均跨分类和立场。对照差异以所提交的前期文件内容为范围。历史 H 只比较意义，不进入本期seed、路由词、标题证据或引文。先读 E 的历史提示；实际核心检索若给 history_candidate_feedback.json，一次补齐所列旧句核对，不重读整份旧工作台或旧原表。

发现阶段history_review 填实际 checked_candidates、关系、理由和匹配旧组。current_evidence/previous_evidence先由脚本从明确选择的本期seed与已核对相关旧句回填，末端再按实际留样覆盖，不沿用已丢弃seed说明；脚本不推断关系。换作者、演员、例子、集数、标题或播前到播后仍可延续。developed 必须确有判断或机制展开，不设每日新增配额，材料重合时允许点位延续。

## 逐条审展示句

单条样本只须具体支持同一核心机制中的实质判断，不要求一条同时评价标题里的所有演员、实例或细节。全组证据共同覆盖标题并有两份独立有效声音；逐条审样与末端全组核对分工不变。

只按当前 handoff 派 WorkBuddy 原生 Agent，每轮唯一新名字，每包最多6条、每波最多8包；省略 model 继承主窗口。审核者只读指定包。主窗口独占 native_worker_registry.json，累计真实 agent_id、team_name、task_id 与终态。

每完成2条判断，原子替换自己的完整answer_file，保留尚未审核项的空decision，最后不足2条也立即保存；不等全包结束才提交，不覆盖已有通过判定。主窗口仍只收集，不代填语义判断。

每条 keep 须有选定原句、具体 reason 和实际 evidence_focus。整个窗口合格时填 selected_window 序号，需裁剪时填写连续逐字 selected_excerpt。短评至少50字、文章至少70字，最多360字；选项只是同一来源的备选窗口，不是多条样本。确认目标、核心机制、立场、完整性，不照抄分类绕过。错误句在本窗口换片段或 reject，不改原文、不拼接、不用上下文补论据、不重新归组。

全波派发后立即执行 collect_command，不先睡眠或查文件。返回 repeat_command 就执行；缺答不启动重复写者，REPAIR_SUBMITTED_ANSWERS 先修反馈，已通过项不重审。全部写者完成后关停本期上一轮成员，再派新轮。连续300秒无新增判定时仅按控制器的 STALLED_REVIEW_RECOVERY_REQUIRED 做一次实际 TaskStop、shutdown 与 recover-stalled；不能代填未读判断。

每组尽量审到10条独立有效样本。派审优先照顾已留样本最少的组。达到6个正面点后继续补审，直至候选用尽、已满10条或只剩末端核对与交付所需时间。派审前每组最多预占其剩余展示名额所需的来源，不能以未派出的多余候选占住其他组的来源；同一来源仍只派一个组，原评分、来源优先级和逐条审核不变。缩小批次与编辑收尾预算由脚本决定，next_wave_required_seconds 已含保留时间，不重复相加。不提前 finish 跳过已批准新包，不把未审记为 reject。部分结果必须如实报告。

## 候选任务收尾与时间分配

## 一次末端证据核对

本版在45分钟清洗预算内预留最多480秒做一次末端编辑及标题证据核对，另保留收尾时间。当前主窗口直接读 display_editor_input.json 一次写答卷，不另起编辑 Agent，不增加一轮原表复审。

retained_evidence 是全部实际留存展示句，只用于确认最终标题、近义边界和入稿选句；editable_samples 是每组最多2条可 keep/trim/exclude 的风险/代表句。标题只能在原方面和判断内收窄失据细节，不能恢复已丢失seed、另造新观点或扩大成整体好坏。按 claim_index 绑定每个标题分句的实际展示原句，core_mechanism 同步收窄。

近义组可 merge_into 证据更具体的同方面同立场组，说明合并原因；不合并机制不同的批评。合并后仍最多10条，必要证据和优选句优先保留，未展示的已审项留审计，不伪称内容不合格。空组不计实际点位。

writing_guidance 同时填standalone_eligible与independent_voice_ids，区分可补充引用与有至少两份独立声音、可单独成段；近同稿只算一份。为每个可入稿组优选1—2条具体、互补的已审句及连续支持片段；只有泛赞、名单、履历、宣发热度或不足以成文时 eligible=false。没有具体声音就少写，不为点数填充。有历史的全部组复核实际旧句，history_candidates编号对应顶层去重history_samples；history_check绑定1—2条当前实际留样证据，continuing也不能保留已丢弃细节。旧句尾部已出现的判断不能称新。写完立即 editor-collect，仅修反馈项。

已提交且指纹匹配的非空末端答卷，只要清洗硬截止未到，就执行全部校验；不因剩余时间少于静态180秒收尾预留而直接丢弃。未提交、空模板、证据不合格或真正过期仍不得通过。

没有完成本次标题证据核对就不冒称本版完整通过，不改时钟或跳过标准。此步骤仍不等于全量原表或全部展示句逐条二审。

## 写稿只承接工作台

读 [writing.md](references/writing.md)。只用当前实际工作台 final_dataset.json 的展示句和元数据，不读原始 Excel、候选池、抽取记录补样，不把历史句写进今天。发现缺口记录在后台，不在写稿时修补聚类。

逐轮确认本期自己启动的原生任务已完成或实际停止，发 shutdown_request；不反复等已 completed 的任务。只对本会话自己的自动团队做 TeamDelete，留下真实成功记录，及时结束；不操作其他会话团队或原表。

聚类硬下限补缺每包最多144条发现摘录，只排除已被其他展示样本占用的来源；去掉内部猜测的方面、正负面及排序分数，不因处于列表后部而丢弃线索。初审数量达标不代替末端独立成段判断，补缺须读取已有末端证据缺口；先完成硬下限审核；已锁定后的补审按增量流程逐批运行。新增观点与样本照常审核，原始时钟不变。

标题的同一分句可绑定多条真实互补原句，每条仍校验归属、逐字出处和实际展示；不因提供第二条有效证据而触发格式返修。旧作评价加未来预测不计为本剧已实现的效果，主创意图与外部评价分清。

补缺使用后恢复普通预算，审核门槛与原时钟不变。对象指代识别覆盖“整部剧、这剧、剧宣”，仍须真实局部剧名锚点、逐字来源及AI承接判断，不允许救援别作评价。


补缺先依据末端标题和独立声音审核确认真实缺口。非空工作台先审核再补缺；只有证据发生变化才重新做末端审核。常规审样预留1350秒，覆盖首次末端审核及可能的补缺、再审核和收尾，不增加总时间。补缺新增只收正面观点，错误反馈定位到具体不合格项。已有6组时不为弱备用点重复补审；头条过半的合格正面组可查同等相关的其他来源。每个计数声音须支持同一个核心判断。

纯段落字数返修仅发问题段及其对应工作台组的完整已审句，保留绑定和原验收；涉及跨段交叉、观点更换或图表的反馈仍提供全局材料。相邻段使用同一起句动词时，在生成Word前反馈到后段，由模型选择含义适合的其他动词。正文合并后完整校验，终审须重新通读实际终稿。

小批补缺使用上一批首次交卷的耗时估算启动开销，保留审样和末端审核预算。补缺无新增展示样本时沿用已完成末端审核，实际增样后再次审核。

终审明确定位到局部段落且归组不需调整时，只重送该段与同组已审原句。两条充分声音可以按原例外规则保留短段，删掉重复之后不以相似引文回填。脚本完整校验，修订稿仍全文终审。

补缺提议预先核对已留样本的逐字重复及已审候选摘录哈希。多作品文章在原窗口缺少作品指代时，可增加一段接上紧邻主语的连续候选窗口，仍由模型逐条审核，其余核对用上下文不可作为引文。

发现阶段给摘录标记同源编号，先用两份独立原句定位实际共同评价，再定正面标题；热度、名单、上线和剧情简介本身不占正面观点名额。补审有新增留样时，新末端核对归档前一轮答卷和反馈，按本轮证据生成独立绑定，不沿用旧指纹。

末端分别核对来源是否独立与观点是否交叉。不同作者各自作出的同向具体评价可以相互印证，转载、照搬和同一来源的转述仍只计一份。
观点发现也执行现有展示长度要求；必要时从同一来源衔接紧邻的完整原句，仍须逐条审核实际支持。全段不足下限的线索不进入定题池。

发现阶段一次报告全部标题证据绑定错误。E编号和逐字片段同时给出且确指同一E时，保留该逐字片段；冲突仍要求修正。补交边界说明保留已有通过项。

确认正面缺口后，从同一冻结原表的未审来源按既有方面分批召回最多32条原句，与原发现池可用摘录合计不超过144条。优先送审模型实际引用的新增证据来源，每条仍按原标准逐条审核，写稿只读已审工作台。

末端按初次发现的相近正面观点对检查实际留存原句。若两组都要独立成段，给两组各一条体现区别的证据。跨方面近义可合并为证据更充足的一组；不自动迁移跨方面引文。

聚类补样明确绑定支持原句。原句在同一来源的随附短上下文时，可在逐条审核前扩成连续送审窗口。首轮结束后最终独立观点仍不足，若时间充足可追加一轮更小的补缺，保留旧决策与原截止。

聚类中的实际观点风险对会随工作台传入提纲和终审。分别成段时须用两段各自选入的真实引文证明区别，修改后重新核验。

多作品来源的指代返修会标出仍可选择的原文窗口及原编号。脚本仅排除结构上无作品指代的窗口，实际语义决定仍由审核模型完成。

发现与补缺材料提供匿名作者编号。同一作者的不同记录不能充当两份声音，补缺不能重新提交与已有组完全相同的种子集合。

发现与补缺包附有原句定位索引，以不同作者的少量具体措辞提示容易被长材料淹没的方面。所有观点和样本仍由模型按完整原文审核。

少量作者提供具体同类措辞时，初次发现答卷需说明是否能形成独立点。提示只决定查哪些原句，模型决定其立场和是否成立。

表演评价召回兼容“把人物某种状态演出来”等直接演绎表述。局部窗口只谈其他作品时不因标题提到本期而进入具体评价探测，优先原句内有本期名称的材料。

具体评价线索优先陈述句，泛问“够不够、是否”等不占稀少方面的定位名额。近邻别作筛查仅用于表演定向召回，避免片中宣传活动提及综艺时误伤动作评价。

程序化审样和字段返修使用repair_packets.model_view(task)提供当前包短证据编号；apply/merge自动一一还原原始ID再完整校验。CLI prepare返回read_now指向短编号输入，task保留原指纹绑定。不得在原始账本重编号或手工猜补错误哈希。

模型所读错误信息中的样本编号与本包短编号保持一致，原文证据字符串不作替换。网络型调用失败可在原时钟内有界重发，不能复用旧稿终审。

发布工作台前，控制器用单独小包核对每个拟计数正面点的两条核心原句及相互边界，包含逐句判断。未通过的组退回现有有界聚类补缺，不进入写稿；补样改变证据后重新核对。此包复用editor-collect入口，按当前schema答卷。

一条来源可支持多个候选方面时，脚本先给可用来源较少的正面点保留两条发现证据的审样机会，再补充已有充足材料的组；仍须逐条语义审核，样本最终只属一组。成稿通常择优写6个正面段，可合并相关互补点或舍弃备选，不强行使用工作台所有观点。

人工选材不强制引用自动优选句，避免要求引用未选材料；仍须在选材提纲逐段绑定至少两份独立有效声音，并经过逐字、观点、具体证据和全文终审。


### 证据粒度统一

证据按完整观点核对，不按一个细节卡死：同一集中评价主题可以由互补的具体子评价支撑，如演唱听感与歌曲人物适配共同支撑原声音乐感染力，服饰与置景共同支撑同一视觉风格。每份声音都须有对本主题的实际评价，每个标题分句至少一条具体证据，全段至少两份独立声音；不要求每条引文重复同一细节或同时覆盖所有分句。不能仅因都提到演员、音乐或预告就合组；不能把无关问题装进泛泛的整体很好，也不能与别段重复核心评价。独立来源同向互证与不同细节互补均可，纯资讯、名单、期待及同稿转载均不能补足证据。


### 短段复核口径

sufficient_development判断信息是否充分，不等于字数是否达到180。低于常规字数时先回读完整已引展示句与同组备选；若已含至少两份独立、具体且互补的有效评价，论述完整，确无遗漏的必要信息，并能说明该观点的独立价值，可填keep_important_opinion、sufficient_development=true、issues=[]；这不是自动通过，其他审核项仍须全部通过。若是单源、泛赞、资讯、遗漏可用细节或关键判断缺证，则仍应返修或删点。不能一面判有充分实质信息并保留，一面仅因字数把sufficient_development置false；也不能为了达到字数添加无证据的解释。


初次发现按实际证据及时提交；最终六个正面硬门槛仍由末端验收。不得在首次发现内部无界穷举以凑数量。


断点恢复保留原计时：PREPARING可通过advance继续准备写稿；发现阶段的关键词数量问题与其他格式问题一次汇总，不能靠减少关键词或跳过逐字检查提速。


### 有界的两步观点发现

首次发现分为VIEWPOINT_SKETCH_REQUIRED和VIEWPOINT_DISCOVERY_REQUIRED：先依据同一批本期原句交简短草案并sketch-collect，再按完整发现包定稿。草案只是模型自己的整理辅助，不算审核通过；下一步仍读全部原句，补齐社交批评、分句证据、关键词、跨日和风险对核对。两步共用原始计时与同一期绑定，不增加数量特批，不绕过最后六个正面门槛。

末端核心证据审核会展示同组已经逐条审核保留的样本。原先推荐片段没有截到评价时，模型可在此池中重新选两条连续原句，并重新核对核心支持、作者独立与跨组重复；不得因两条推荐选错就断言全组无证据，也不得从原表补样或推断通过。


本版直接执行正式观点发现，不再单独调用模型生成未审草案。正式发现仍读取全部本期原句并完成原校验；逐条审样、末端证据核对、提纲和全文复核均保留。
概括层级：先从本组全部retained_evidence选出两份支持同一评价的独立声音，再概括最终标题。标题概括评价，不把其中一条的场景、动作或人物名字变成整组必须满足的条件。原核心有两份充分支持时保留；只有失据的判断才删减。两个不同场景都具体支持同一种表演效果，可以相互印证，不必同演一场戏。反过来，不得把实际上不同的评价装入“整体很好”。如果最终仅一条证据成立，照实标记补充，不通过改标题制造第二条。

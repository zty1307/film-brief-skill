# r74候选：负面观点先核对现有社交批评

基于本地r73候选继续开发，尚未推送或替换已安装Skill。用户要求在不增加原始样本的前提下，试行“先核对微博、小红书真实批评，再确定最多3个负面观点”。

## 改动

- 保留r73的正面至少10组且不拆近义、正面/客观表演观点最多2组，以及负面合格候选的微博/小红书、公众号、媒体排序。
- 观点发现包总量仍为每个粗方面/倾向最多6条、整期最多144条。负向粗分的一个代表位置可带入现有原表里含批评线索的社交摘录，即使其通用热度分偏低；词法线索只用于供模型核对，不是负面结论。
- 同一次观点发现答卷必须逐条判断输入中的微博、小红书代表摘录是否真在批评本剧，并记录每条对应的负面簇或未入选原因。真批评先参与负面主题取舍，再与公众号、媒体证据核对；不因渠道强凑观点，也不增加模型轮次或原始数据。
- 保留r72/r73的原文溯源、明确AI稿排除、长度门槛、自适应补样和离线HTML模板。

## 背景与验证

- r73在同一批《金色》原表上的DeepSeek实跑为22分14秒、128条、正11/客1/负3组、待审0；19条负面样本没有微博或小红书。发现输入136条中含真实的小红书批评，如“剧情偏慢”“尹昉动作舞蹈痕迹重”，但这些机制未成为该轮最终负面观点。r73的GLM另有25分08秒、51条、10条未审的部分交付。
- r74离线prepare读取同一批5份原始Excel、4,374条记录，生成136条代表摘录；其中现有社交批评线索已进入发现包，未增加原始记录或代表摘录上限。social_review_ids随包列出，模型在同一次答卷核对。
- tests/test_r74_social_negative_review.py覆盖审计记录完整性、真批评只关联负面簇、否定式好评过滤，以及低热度社交批评进入负向发现包。原有回归脚本继续通过。
- 第一次冻结版DeepSeek实跑用时23分33秒，142条、正11/客2/负3组、待审0、编辑完成，但最终18条负面样本仍全为公众号/新闻。追查发现：小红书“节奏有点慢”被错误挂到“节奏仓促”组，终审正确拒绝；另一条“动作舞蹈痕迹有点重”因标题扩写到“首次担纲、气质待验证”且整帖混合赞赏，也被拒绝。
- 据此补充同向标题约束、观剧后第一手批评优先级、混合语气评论判定规则，并用确定性节奏方向检查拦住“慢/仓促”错配。第二次冻结版DeepSeek同一批原表实跑用时21分20秒，123条、正11/客0/负3组、待审0、编辑完成、结构PASS、Skill运行时未改，30分钟内完成。最终负面样本17条，其中小红书1条：开局节奏偏慢组的唯一原评，来自原表小红书第707行，连续摘录明确指出“节奏有点慢”“第一集……很可能就坚持不下去了”；另两组仍为公众号/新闻。全台123条对原始Excel单元格与片段位置独立核验，0处不一致。
- 这证明在不增加原始样本时，现有社交负评有机会进入最终结果；不保证每个负面观点都有社交样本。表演“舞蹈痕迹”被标为轻度批评但未入最多3个负面观点，因而未成为最终样本。节奏组只有1条，不能据此推断该意见普遍。

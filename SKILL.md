# Film Brief Cleaning

Produce a traceable source-level run, not a report draft. The output is an information workbench: each period contains data-derived viewpoint clusters and multiple independent source samples that a human can later merge or rewrite.

## Mandatory controller

For every new production run, use `scripts/film_workflow.py`. Do not ask the model or operator to remember the stage sequence and do not call `film_pipeline.py` directly except while diagnosing a failed gate. The controller creates an isolated workspace, records input and stage-output hashes, advances deterministic stages in order, emits one machine-readable `workflow_status.json`, and stops whenever a semantic review is required. It also owns the verified-workbench merge entrypoint.

Resolve `<python>` from the Codex bundled workspace dependencies before running commands; do not rely on the Windows Store `python` alias. Run the preflight check first, then start with either initialization form:

```powershell
<python> scripts/film_workflow.py doctor --source <原始数据目录> --period-config <period_config.json> --workspace <独立工作区> --output <单期工作台.html>
<python> scripts/film_workflow.py init --source <原始数据目录> --workspace <独立工作区> --output <单期工作台.html>
<python> scripts/film_workflow.py init --source <原始数据目录> --period-config <已完成的period_config.json> --workspace <独立工作区> --output <单期工作台.html>
```

Then repeat only this command until `status` is `COMPLETE`:

```powershell
<python> scripts/film_workflow.py advance --workspace <独立工作区>
```

When the controller returns `REVIEW_REQUIRED`, read the stated `input_file` or `input_files`, follow every item in `review_requirements`, copy the generated template from `review_templates`, complete the named `required_file`, and preserve its `_workflow` block exactly. Never reuse a review file from another workspace. When it returns `READY_TO_ADVANCE`, run `advance` again. `BROKEN` or `BLOCKED` is a real failure, not permission to skip the gate. `COMPLETE` still requires opening the HTML once for visual inspection before delivery.

The controller's canonical review filenames are fixed under `<独立工作区>/reviews`: `source_reviews.json`, `dedup_reviews.json`, `cluster_definitions.json`, `cluster_overrides.json`, `cluster_set_reviews.json`, `cluster_member_semantic_reviews.json`, optional `excerpt_reviews.json`, and `final_excerpt_semantic_reviews.json`. A different AI must use these exact files rather than inventing alternate names or carrying forward an older run's answers. Never run two `init`, `status`, or `advance` commands against the same workspace at once; the controller uses an operating-system file lock on `workflow.lock` to reject concurrent access, and the operating system releases that lock automatically when a process exits or crashes. The file may remain on disk and must not be interpreted or deleted as a stale PID marker.

## Required workflow

For a complete run, read [workflow.md](references/workflow.md), [contracts.md](references/contracts.md), and [review-rubric.md](references/review-rubric.md). The controller enforces these stages in order:

1. Inventory and normalize the raw channel exports with `scripts/extract_sources.py`.
2. Create a period configuration from the current data. Separate exact work anchors (`strong_terms`), ambiguous shorthand (`weak_terms`), people or role helpers (`auxiliary_terms`), and comparison works. Use the core-plus-verified-extension parent-entity registry in `assets/media_subject_registry.json`: keep the preloaded core small and stable, and add a new subject, exact account alias, or first-party domain only after AI or human verification through `media_subject_extensions`. Match an exact reviewed account alias first; when a news article is signed only by a reporter or has no account name, use an exact verified first-party domain as fallback. Certification information is a last auxiliary route: certification type must be media and the certified entity must uniquely match a reviewed parent or a reviewed alias of at least four Chinese characters. A generic media badge alone never grants mainstream status. Never infer authority from an aggregation, syndication, social-platform, or repost host. Official vertical accounts inherit their verified parent's tier across channels, while names that merely contain 新闻、日报、媒体、电视台 or 网 are not promoted. Then run `scripts/film_pipeline.py prepare`. Set `content_mode` to `serial_drama` for continuously updated drama or `episodic_variety` for weekly variety. `prepare` may discover hashtags that repeatedly co-occur with explicit work anchors, plus recurrent current-period event tags; these terms only route otherwise target-omitting comments to AI review and never auto-admit them. It hard-excludes a whole source when the source itself contains an explicit AI-generation disclosure, a drafting instruction, or model meta-output; ordinary discussion of AI remains eligible.
3. Review every item in the generated source semantic queue from full source text. Use the exact candidate spans and character positions emitted by `prepare` when possible. For `episodic_variety`, attribute every otherwise eligible source to the latest episode, a newly prominent topic from the immediately previous episode, current program-level discussion, or out of scope. The latest episode is the main pool; an earlier episode is admitted only when a new topic becomes conspicuous during the current monitoring week, with its prominence basis recorded. Save only current-period decisions in the review contract; a release cannot pass while `source_review_queue.unresolved.jsonl` is non-empty.
4. Run `scripts/check_links.py` on `normalized_sources.jsonl`, then pass its result to `select --link-health`. Only a 404 or 410 reproduced by two GET requests is a deletion gate. Login walls, 401/403/429, anti-bot responses, 5xx, DNS errors and timeouts remain indeterminate and cannot delete a sample. Run `select`; inspect duplicate candidates and preserve independent authors expressing similar views.
5. Read the retained sample, derive this period's clusters without using a prior report, and label every cluster `positive`, `objective`, or `negative` before running `cluster`. Cluster by a shared evaluative mechanism or reportable proposition; a performer, character, guest, segment, meme, or metric is normally an evidence facet, not automatically a top-level viewpoint. Do not require or target any sample count per cluster. Keep semantically independent small signals and every qualified independent expression.
6. Complete the cluster-set review produced by `cluster`, then rerun `cluster` with `--set-reviews`. Review every non-empty cluster from the assigned current display passages, using full source text only to resolve target, scope, source role, or to re-excerpt. Verify that each clause in the title has member evidence and that every cluster member is mapped to at least one title claim; for each member, record a verbatim support span from its assigned passage and the title-claim indices it supports. A list of source IDs without member-level evidence cannot certify a broad mixed cluster. Review the whole period at the same time: a normal single-period workbench should usually contain 9–16 final one-level clusters. The script only counts, fingerprints, and blocks unresolved reviews. AI checks clusters above 16 for name-based or fragment-based over-segmentation, and clusters below 9 for omnibus titles that contain distinct mechanisms. Revise titles and membership only when every member still supports one precise report-style proposition; never delete qualified samples, invent viewpoints, or merge unlike propositions to enter the range. A justified out-of-range result is allowed only with an explicit exception review. Then give `cluster_member_semantic_review_input.json` to an independent second AI pass or a context-reset audit. It must judge each member against the final cluster title and local stance, write its own verbatim passage evidence, and be supplied through `--member-reviews`. `render` remains blocked while cluster-set, period-count, or member-semantic review is unresolved. Also check drama time status or variety episode scope, official or participant statements versus independent public consensus, and whether the set is over-broad or fragmented only by names or isolated segments. Classify each final cluster as a report point, subtopic, data note, or rare signal. The workbench presents these final clusters directly in one level under positive, objective, and negative tabs.
7. Resolve every low-confidence assignment with four checks: target work, aspect, local passage stance, and verbatim evidence must all align. Multi-work articles require passage-level target attribution. A whole article's reversal, comparison, plot recap, or mixed stance does not disqualify a self-contained aligned passage. Keep uncertain sources in the retained pool, but exclude unresolved passages from display. Within each cluster, put verified mainstream-media accounts before other sources regardless of whether they appeared in news, WeChat, Toutiao, Weibo or Xiaohongshu; use channel and quality only as later ordering keys. This priority never bypasses content gates or deletes independent non-mainstream expressions.
8. Review display excerpts and run `render`. If an initial passage is mixed, incomplete, or points to another work, search the same full source for an aligned passage before excluding it. Then complete the independent final-excerpt semantic review generated by `render`; this review must judge the final excerpt itself and must not reuse `passage_stance`. It may return `keep` or a source-specific `drop`; every drop records failed checks and confirms that full-text re-excerpting was attempted. When a passage fails only because its aspect or stance does not match the provisional cluster, search the other current-period clusters and create a new data-supported cluster when necessary; do not discard a valid target-work opinion merely because its first assignment was wrong. Reviewed drops are recorded and omitted, while malformed, missing, or template-repeated reviews block release. If excerpt review empties a cluster or changes the final cluster count, `render` must stop and require renewed cluster-count review; it cannot silently publish a smaller set. Positive clusters contain only positive evidence, negative clusters only negative evidence, and objective clusters only neutral facts, balanced observations, or explicit sentiment-distribution evidence. Excerpts may use one or two verbatim source spans in source order; never rewrite or fabricate text. Prefer 70–150 display characters and include both a complete judgment and at least one concrete supporting detail. For an excerpt below 70 characters, re-read the full source and extend it with aligned evidence. A shorter excerpt may remain only when the source cannot be extended and it still contains a concrete, verifiable detail such as a specific line, action, plot point, performance treatment, disputed fact, or analytical basis. A work hashtag, person name, or generic reaction such as 好看、封神、绝了、笑点拉满 or 期待 is not supporting detail; if nothing more specific exists, exclude the item from the display layer even though its target and stance are identifiable. Excerpts over 150 characters are rejected and must be tightened without cutting sentence boundaries. Before semantic review, `render` recognizes both conventional paired topics and adjacent leading-hash tags; in a terminal tag run such as `#节目#嘉宾`, the second `#` starts the second tag and both tags are removed. It also deterministically removes account mentions, platform emoji/emotes, Markdown or raw links, and video-share boilerplate while preserving the exact raw spans and character positions for provenance. Do not copy words out of a hashtag merely to lengthen or re-anchor a display excerpt. The source-level target and episode audit may use the raw hashtag as context, while the visible workbench card and cluster heading provide the reader with batch and period context; a short but clear opinion does not need to repeat that metadata. If cleanup leaves only hashtags, mentions, links or a slogan with no independent prose, exclude the source as non-displayable content. The script flags excerpts containing raffle, ticketing, registration, QR-code, gift-pack or similar operational promotion terms; AI may keep them only after locating a complete independent opinion in the excerpt, otherwise it must re-excerpt the same source or drop it. Keep every qualified independent expression regardless of how many samples the cluster already contains; sample count is never a reason to keep or drop an item.
9. Run `verify`. Open the generated workbench for visual inspection and report sample count, final one-level cluster count, and any unresolved items separately.
10. After every standalone workbench passes verification, run `scripts/film_workflow.py merge` when a cumulative workbench is required. Put the existing cumulative workbench first and the newly verified standalone workbenches after it. A batch with the same name is replaced in its existing position; a new batch is appended. The controller serializes writes to the destination, while the merge command preserves the first page's visual shell, validates all incoming current-format batches, accepts older schemas only from the first cumulative base, backs up an existing output, writes a merge verification report, and replaces the destination atomically only after the merged HTML passes validation.

Do not skip a stage because an older run already contains decisions. Reuse stable mechanics and schemas; regenerate target aliases, semantic judgments, cluster names, terms, and overrides from the new period.

## Non-negotiable boundaries

- Admission starts from current source title, body, ASR, and necessary parent context. Strip old scores, report hits, cards, old clusters, old excerpts, and earlier machine or human decisions before screening.
- Historical finished reports may be used only after the candidate output is frozen, and only for separate evaluation. They must never force retention, supply cluster answers, or alter blind-run decisions.
- Deduplicate copies, reposts, and clear rewrites of the same manuscript. Do not delete independent sources merely because their viewpoint is similar.
- If one mainstream-media account distributes the same manuscript across platforms, treat those copies as one source family. Prefer the complete, stable-link version; platform count does not turn the same manuscript into independent consensus.
- Mainstream-media promotion uses exact reviewed account aliases and verified first-party domains. An alias match takes precedence; domain fallback is allowed only for the media organization's own host when the byline is a reporter or absent. Account identity outranks channel, but does not prove relevance, stance, quality, or audience consensus. Program accounts, broadcaster-platform accounts and participant accounts are first-party sources, not automatically mainstream news media.
- Explicit AI-generation disclosures, leaked drafting prompts, and model task/output meta-language are source-level hard exclusions. Do not salvage a local paragraph from that source. A normal article about AI is not excluded merely because it mentions AI.
- Link deletion requires a reproducible HTTP 404 or 410 in `source_link_health.applied.json`. Never interpret login requirements, anti-bot blocks, 401/403/429, server errors, DNS failures or timeouts as deleted content.
- A quality score ranks and orders candidates; it never independently deletes a source that already has a target, a judgment, and supporting evidence. Lower-scoring valid expressions enter `retain_consensus`.
- Comments and reposts must contain a usable viewpoint in their own text. Parent text may establish the target but cannot replace the author's evidence.
- Actor, guest, creator, and character names are auxiliary terms. They cannot independently admit a source. Ambiguous shorthand can only send a locally supported item to AI review; automatic admission requires an exact work anchor and a nearby judgment with supporting detail, or an exact single-work title plus such a judgment.
- Recurrent hashtags or event names learned from the current period can recover comments that omit the work title, but only into the source AI queue. AI must verify from full-text context that the event belongs to the target work and record exact evidence; recurrence is not proof of target attribution.
- A source-level target match is not enough for display. The selected passage itself must refer to the target work, or an AI review must record exact target evidence from the same source. If the passage mentions multiple works, AI must identify which work each judgment belongs to.
- Judge stance on the selected evidence passage. A positive cluster may use the positive passage of a mixed article, and a negative cluster may use a separate negative passage from the same article, provided the passages do not overlap and each is independently complete. Do not create a negative section merely to balance the page when the current period has no clear negative evidence.
- Short video without usable ASR is excluded from the text-evidence pool.
- Weekly variety is episode-centered: analyze the latest released episode first. The immediately previous episode may enter only for a newly prominent current-week topic supported by cross-source spread, engagement, authoritative pickup, or substantive risk; routine carry-over discussion and older-episode material stay out of scope. Drama uses the continuous story and daily-update window instead of this episode gate.
- Display excerpts must not contain hashtags, emoji, platform emote tokens, account mentions, Markdown links, raw URLs, or shared-video boilerplate. Their removal is a deterministic display normalization recorded in provenance; it never licenses AI paraphrase.
- Display length uses the cleaned excerpt. The preferred range is 70–150 characters; 150 is a hard maximum. A shorter complete opinion is allowed only after full-text re-excerpting cannot add aligned evidence, it still contains a concrete supporting detail, and both the exception reason and verbatim detail are recorded. Generic praise or criticism without detail is not a display sample. Never add unrelated background merely to reach the preferred minimum.
- Pure ticketing, raffle, registration, giveaway, QR-code, scheduling, cast-profile, or campaign-instruction text cannot support a viewpoint. If the same source also contains a complete judgment with evidence, keep that judgment after removing the operational wrapper; source type or promotional context alone is not a deletion reason.
- Every AI decision records a source ID, decision or cluster, reason, and verbatim evidence. Every excerpt must pass deterministic source-position validation and a separate final-excerpt semantic review covering target, aspect, stance, work-internal consistency, and self-contained meaning.
- A cluster title must be a directly understandable report-style proposition beginning with or containing a clear reporting predicate such as 肯定、认可、关注、讨论、质疑、批评、担忧、认为 or 指出; `记录` is reserved for `data_note`. Short noun labels are rejected.
- Every clause in a cluster title must be supported by current members. Do not expand a narrow set of samples into a wider claim, and do not use a person or segment name as the only clustering principle. Report-role labels help review but never change source admission or erase samples.
- Present one level of final clusters. Keep positive, objective, and negative clusters separate. Treat 9–16 clusters per normal period as a review range for reader workload: preserve every qualified sample, require semantic evidence for every regrouping, and allow a justified exception when the data would otherwise be distorted.
- Cluster membership is justified from the final assigned passage. Every member must provide a verbatim passage-level support span and identify the title claim it supports. Full body text may resolve context or supply a replacement excerpt, but unrelated words elsewhere in a long article must not widen the cluster meaning.
- `data_note` records relevant facts, metrics, schedules, official announcements, participant statements, or balanced context. A fragment that contains neither a usable opinion nor relevant factual context cannot be kept under a catch-all title such as “未形成完整评价” or “当前片段中的相关事实”; re-excerpt the source or exclude it with an auditable reason.
- Drama clusters distinguish pre-broadcast expectation, current broadcast reaction, and later reputation when those statuses occur in the monitoring window. Variety clusters distinguish the latest episode, a separately evidenced newly prominent previous-episode topic, and current program-level discussion. Mixed scope is allowed only when the title states it and the cluster-set review explains why the combination is reportable.
- A variety item's `episode_scope` is source-level audit evidence and must remain unchanged during clustering or workbench generation. Every ordinary variety cluster must contain only items whose stored scope equals the cluster scope; move the item or split the cluster when they differ. Never rewrite item scope from the cluster label to make validation pass.
- Official accounts, program participants, and promotional media can supply background or attributed statements; they do not by themselves prove independent audience consensus. A single metric or isolated factual update is a data note unless current opinion interprets it.
- The workbench is a single local HTML file, contains no remotely loaded assets, and never embeds or auto-opens `*.woa.com` links.
- A cumulative workbench is assembled only from verified standalone workbenches. Do not copy JSON by hand or regenerate the cumulative page with a different template. The merge must preserve unaffected batches byte-for-byte at the data-object level and preserve the base page outside its embedded `DATA` block.

## Tool division

Use scripts for file reading, stable IDs, field isolation, explicit AI-draft leakage gates, exact reviewed media-account and first-party-domain lookup, safe link checks, scoring, exact-copy checks, similarity calculations, source-position checks, audit counts, and HTML generation. Use AI for verifying new or ambiguous media identities before aliases or domains enter the registry, target-focused full-text review, irony and mixed stance, distinguishing independent expression from wash-copy, deriving period clusters, resolving ambiguous assignments, rescuing useful passages from mixed articles, and choosing and independently validating the clearest verbatim excerpt.

Do not claim completion from a generated page alone. Completion requires the latest `render_summary.json` to be `RENDERED`, an empty `render_failures.json`, exact equality between the HTML embedded data and `workbench_dataset.json`, and `verification.json` with `status: PASS`, zero unresolved source reviews, cluster-set reviews, period cluster-count reviews, independent cluster-member semantic reviews, assignment reviews, and final-excerpt reviews, zero target/aspect/stance/work-consistency/provenance failures, and a visually checked workbench. Report sample and final cluster counts separately. Do not achieve PASS by silently moving queued semantic decisions into a recovery pool.
